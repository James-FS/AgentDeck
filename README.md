# AgentDeck

AgentDeck 是一个运行在本机的 Web 工具，用于盘点和管理 Codex、ZCode、Claude Code 与 DeepSeek Harness 的部分本地 Skill、插件和 MCP 配置。也可以直接登记独立 Skill 目录，不要求先安装或发现客户端。

它帮助你查看资源来源、配置状态和使用范围，预览 Skill 内容，对比不同副本，并跟踪目录变化。**磁盘发现、配置启用和客户端实际加载是不同的状态**；AgentDeck 不会启动 Skill、插件或 MCP 服务进程。

## 功能概览

| 能力 | 当前支持 |
| --- | --- |
| 客户端与项目盘点 | 自动发现客户端，手动登记实例和项目；区分配置记录、插件缓存、用户公共来源与项目来源 |
| 独立 Skill 资源库 | 登记单个 Skill、集合或项目/插件目录；快速/深度扫描，保留格式问题候选、跳过原因和截断位置 |
| 详情与搜索 | 完整描述、常见元数据、`agents/openai.yaml`、支持文件清单、安全 Markdown 预览及分页内容搜索 |
| 项目可用性 | 独立检查表单：选择客户端、项目和工作目录后点击检查，区分当前文件/格式状态、扫描时配置状态、同名冲突和范围不匹配 |
| 日常操作 | 收藏、保存筛选、复制路径、打开可信来源目录，以及两个已发现 Skill 的对比 |
| 更新与变化 | 自定义来源增量重扫、强制完整扫描、可选目录监听，以及来源和客户端扫描变化记录 |
| 受限配置修改 | 对明确支持的单项配置启停、预览差异、记录操作，并基于备份准备恢复计划 |

## 快速启动

### 环境要求

- Node.js `>=22.12.0`，仓库 `.nvmrc` 指定 `24.7.0`。
- pnpm `11.22.0`，由根目录 `package.json` 固定。

如果尚未安装 pnpm，可在安装 Node.js 后执行：

```sh
npm install -g pnpm@11.22.0
```

### Windows 双击启动

双击仓库根目录的 **[启动 AgentDeck.cmd](启动%20AgentDeck.cmd)**。

入口调用 `scripts/start-agentdeck.ps1`，检查环境及依赖/构建指纹后启动服务，并自动打开带一次性连接票据的浏览器页面。首次运行或状态无法验证时同步依赖并构建；无变化且产物有效时跳过这些步骤。首次同步依赖可能需要联网。请保留服务窗口，关闭窗口或按 `Ctrl+C` 即可停止服务。失败时窗口会保留错误信息。

需要强制更新依赖并重建时运行：

```powershell
.\scripts\start-agentdeck.ps1 -Rebuild
# 或：.\"启动 AgentDeck.cmd" -Rebuild
```

指纹分别校验锁文件、workspace 清单、Node/平台、依赖链接目标，以及源码/构建配置/脚本和产物内容（含网页资源文件）。删除源码或产物也会失效；仅在相应步骤成功后更新 `work/startup-state.json`。构建失败不启动旧产物。终端的 `pnpm start` 仍直接使用已有构建。

一键启动在未设置 `PORT` 时使用 `0`，由系统分配可用端口，避免固定端口被占用或被 Windows 保留。已设置 `PORT` 时会使用指定值。实际连接地址以终端输出为准。

### 终端启动

在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

`pnpm start` 默认监听 `127.0.0.1:4780`，由同一服务提供构建后的网页和 `/api/v1` API。它不会默认自动打开浏览器；请打开终端打印的完整连接链接。设置 `AGENTDECK_OPEN_BROWSER=1` 可让此入口自动打开浏览器。

Windows PowerShell 下如需自动分配端口：

```powershell
$env:PORT = '0'
pnpm start
```

也可以通过 CLI 启动同一本机 Web 服务：

```sh
node apps/cli/dist/index.js serve --port=0
```

CLI 同样需要先安装依赖并完成构建；当前只提供 `serve [--port=4780]`，没有独立的资源管理命令。

## 常用流程

### 资源库与浏览上下文

资源管理默认打开“资源库”，按 **唯一资源实体** 展示：同一物理 Skill、同一插件身份或同一 MCP 服务聚合为一行，缓存版本、配置记录和独立发现入口在详情中逐条列出，不再以可展开的版本树占用主表。聚合仅用于展示；收藏、对比、启停和打开目录仍指向真实的绑定或发现引用，多绑定实体的每个开关分别定位。

资源库使用“我的资源”显示策略，提供两个持久化开关：**显示 Agent 内置资源** 与 **显示仅缓存资源**，新用户默认关闭，收纳在工具栏的“显示选项”菜单中，按钮旁以“显示选项 · 内置”等短标记反映已开启内容。只有适配器验证过的随包来源证据才会判定为内置；没有安装或配置关联的纯缓存记录默认隐藏。开关保存在 AgentDeck 自身数据库，刷新和服务重启后保持，清除普通筛选也不会重置；菜单内给出当前范围隐藏数量（内置与仅缓存两类可能重叠）。搜索提供“包含隐藏资源搜索”入口，开启对应开关后隐藏项才会出现；收藏被隐藏时列表上方保留针对性的提示与显式显示动作。

资源筛选集中在资源库页签内，常驻筛选只有 4 个：**关联客户端**（默认全部）、**项目范围**（全部范围 / 仅全局 / 指定项目，指定项目时默认勾选“包含全局资源”）、**资源来源** 与 **配置状态**。类型页签、搜索、“只看收藏”、“已保存视图”与“显示选项”不算新增筛选。作用范围、所属 Agent、配置或文件来源、资源归类四类技术条件已从常规筛选退出，不再影响列表、搜索、计数与分页；全局/项目边界由项目范围承担，归属、存储位置与分类依据在资源详情和可用性检查中查看，原始扫描证据不变。生效条件以活动标签集中显示在列表上方，可逐个移除；“清除筛选”会同时重置客户端与项目范围和普通条件，保留显示策略开关，也不影响项目可用性表单。资源表上方不再常驻说明，标题旁保留“资源说明”入口，简短说明聚合与加载未验证边界。项目范围语义：

| 选择 | 结果 |
| --- | --- |
| 全部范围 | 当前客户端条件下的全部记录；客户端为全部时另包含独立来源 |
| 仅全局 | 仅 `scope: user-global` 的可靠用户级全局记录；`projectId` 为空或范围未知的记录不伪装成全局，仅在“全部范围”可见 |
| 指定项目，勾选包含全局 | 指定项目记录及当前客户端条件下的用户级全局记录 |
| 指定项目，取消包含全局 | 只显示指定项目记录 |

独立来源保持未绑定，仅在“全部客户端 + 全部范围”下显示；被范围排除时列表会提示原因并提供“查看独立来源”，该动作重置客户端与项目范围并选中独立来源，不会建立客户端绑定。所有条件作用于同一条关联记录，不会用不同绑定分别满足客户端与来源条件。

主表为五列：资源（名称与简述、类型和关系标签）、来源、关联 Agent / 项目、状态、操作。状态以去重后的真实绑定汇总（各绑定一致时显示统一状态，不一致时显示“N 项启用 · M 项禁用”等数量摘要）；独立资源显示“独立发现 / 未绑定”。完整路径、分类依据、安装证据、历史版本和多入口明细在详情中查看；插件和 MCP 详情逐条列出关联记录及其配置文件、配置键与版本。每页 50 个资源实体，页码和统计口径均以实体为准。统计卡与总览展示全部已登记数据，不受资源库浏览条件影响。

顶栏只保留导航与一个“刷新当前页面数据”入口，不再提供客户端/项目上下文下拉；扫描范围由操作本身确定，不读取浏览筛选。

行内提供收藏、名称打开详情和“⋯”菜单（复制路径、打开目录、加入对比）。单一可操作配置保留直接开关与“预览修改”按钮；多个不同控制目标的绑定显示“管理配置”，在详情中逐条启停，不提供汇总开关。对比选择条可跨筛选、分页和页签保留，显示失效资源并允许移除/清空；同一物理 Skill 的多个入口不会伪装成两个副本。

### 发现客户端或添加独立 Skill

客户端资源可通过资源库空状态、资源页“发现客户端”或实例页按钮接入（只读扫描用户级配置），也可在实例和项目页面手动登记配置根、项目根，再执行相应扫描。“扫描客户端”只扫描已登记客户端的用户级配置；“发现客户端”在本机发现目录中发现或更新客户端并扫描其用户级配置，不扫描未登记项目，也不自动执行版本命令。首次尝试也可载入隔离演示数据。

对于集中存放、尚未关联客户端的 Skill：

1. 在“来源与扫描”页签的“添加 Skill 目录”填写目录路径。路径属于运行 AgentDeck 的本机文件系统。
2. 按需展开“扫描高级选项”选择快速或深度扫描，点击“添加并扫描”。可直接登记含 `SKILL.md` 的文件夹，也可登记其上层集合目录。
3. 查看有效 Skill、格式问题候选、跳过原因和扫描完整度。达到上限时，可使用来源行针对性的“继续扫描”入口；该操作会登记一个新的子目录入口。

来源行常驻“重新扫描”、自动更新开关和“⋯”菜单（改用深度扫描、强制完整扫描、复制路径、取消登记）。**取消登记只移除 AgentDeck 登记，不删除目录和文件。**自动更新只对应独立来源的目录监听，不代表客户端配置会被自动监听。深度、限额、缓存复用和逐项发现记录在“扫描报告详情”展开区中。

自定义扫描会显式进入 `.agents`、`.claude`、`.codex`、`.dsh`、`.zcode`、`.cursor`、`.opencode`、`.claude-plugin` 等入口，并跳过 `.git`、`node_modules`、常见构建输出和其他未支持的隐藏目录。示例和辅助目录中的 manifest 不会直接当作独立 Skill。

符号链接和 Windows junction 默认不跟随。可显式开启**只读跟随登记范围内部的链接**；扫描记录逻辑路径与实际路径，并检查边界和循环。范围外的目标需由用户另外明确登记。

独立发现保持未绑定、只读，不会自动安装到客户端。移除资源入口只取消 AgentDeck 登记，不会删除磁盘文件。

### 查看详情、搜索与可用性

- 点击资源库的 Skill 名称或扫描明细中的“查看详情”，查看完整描述、作者、版本、许可证、环境要求、调用方式、工具依赖和支持文件名称。未声明的字段会明确标注。
- Markdown 支持基本标题、段落、列表和代码预览，也可切换“查看原文”。HTML 不执行，链接只允许 HTTP(S)/mailto，外部图片不加载；过长或复杂的行会回退为安全文本。支持文件只列名称，不读取其正文。
- 搜索框统一显示名称/路径匹配及 Skill 说明、作者、依赖和正文命中；输入至少两个字符后防抖查询正文，命中片段回到对应资源行，同一资源实体只展示一次，命中插件子项时直接给出 Skill 阅读入口。类型、来源、上下文、收藏和显示策略与搜索取交集；隐藏资源不会因正文命中重新出现，可使用“包含隐藏资源搜索”显式开启对应开关。分页按**候选资源**推进，当前页没有命中不代表后续没有结果，可点击“继续搜索后续资源”。
- 在“项目可用性”表单中选择客户端实例、项目和(可选的)工作目录，点击“检查可用性”发起检查。工作目录默认使用项目根目录。表单不反向修改资源库筛选；修改任一输入后旧结果会标记为待重新检查。当前磁盘与格式会重新检查；配置状态仍来自最近扫描。

可用性结果属于静态规则推测。客户端版本识别、配置复读和磁盘文件存在，都不能证明运行中的客户端会话已加载资源；没有充分证据时，覆盖优先级和加载状态保持未确认。

### 重扫、监听与扫描变化

| 操作 | 行为 |
| --- | --- |
| 重扫 | 重新遍历受限目录，发现新增/移除，并复用未变化 manifest 的解析结果 |
| 强制完整扫描 | 绕过解析缓存，重新读取和解析；仍遵守深度、数量、大小和路径上限 |
| 开启监听 | 默认关闭，按自定义来源单独开启；合并事件、防抖并串行重扫，通过 SSE 更新页面 |
| 关闭监听 / 取消登记 | 停止该来源的监听；服务退出时等待已启动的监听任务结束，再关闭数据库 |

增量缓存依据来源、实际路径、文件身份、大小、修改/变更时间及扫描选项复用。它是**服务进程内的解析缓存**，重启后重建；增量重扫仍会遍历目录，不等于完全跳过未变目录。来源移除时清除其缓存。

监听开关保存在应用数据库，服务重启时会尝试恢复。若目录不存在、物理位置发生变化、平台不支持或监听报错，页面会显示原因；后台不会自动接受替换后的新根。核对目录后，可手动重扫，再关闭并重新开启监听。

**监听仅覆盖自定义 Skill 来源。** 客户端配置仍通过实例/项目扫描更新。

“扫描变化”页签按以下规则展示：

- 自定义来源保留最近一次有效扫描的变化结果；首次扫描建立基线，新增、移除、manifest 内容或候选状态变化分别列出，每类最多保留 100 条。
- 客户端手动扫描记录绑定新增、移除及配置状态变化，保留名称、路径、项目和状态摘要；最多保存最近 50 次记录，界面展示最近 5 次，每条记录的各类明细最多 100 条。
- 扫描时间变化不作为资源修改；部分或失败扫描不把未覆盖条目当作删除。合法 manifest 变为格式问题候选会记录为修改。
- 自定义来源的内容变化以 manifest 为范围，不表示支持文件或整个包都已做内容差异检查；移除记录也不会删除原始资源。

### 收藏、保存筛选与 Skill 对比

- 收藏作用于资源实体：任一关联引用被收藏即显示已收藏；取消收藏会清理该实体当前已知的全部关联引用，不会因另一条引用立即再次显示为已收藏。绑定资源和独立发现均可收藏，使用“只看收藏”集中查看；被显示策略隐藏的收藏资源会给出可发现的提示与开关入口，不显示成已失效。
- 使用工具栏的“已保存视图”菜单保存、应用和删除命名视图：保存类型、搜索、关联客户端、项目范围与包含全局开关、资源来源、配置状态、“只看收藏”及两个显示开关；旧命名筛选继续兼容读取（已存项目映射为指定项目并默认包含全局，无项目映射为全部范围；“仅用户全局范围且无项目”映射为仅全局），缺少显示开关字段时按默认关闭读取。包含已取消条件（使用范围、所属 Agent、来源类型、资源归类）的旧视图应用时明确提示省略了哪些条件，不会静默扩大结果，也不会自动改写原记录；手动调整条件即离开当前视图标记，需重新保存才会更新。收藏和命名视图在页面刷新、服务重启后保留。失效引用会提示，不会自动改指另一个资源。
- “复制路径”使用浏览器剪贴板；不可用时弹出可手动复制的路径。“打开目录”只接受当前已登记资源引用，并在服务端重新校验路径，不执行资源。
- 在两个磁盘 Skill 上分别点击“加入对比”，再点击“对比已选 Skill”。可比较物理 manifest、名称、manifest 内容、元数据摘要和有界正文；按行位置高亮差异，支持上一处/下一处导航，计算最多 2,000 行、每侧 20,000 字符，插入行可能使后续行显示差异；同名不等于同一资源，manifest 一致也不代表支持文件或整个包一致。

### 修改配置与恢复

扫描到资源不代表该资源可写。项目级配置和未验证的资源保持只读，当前支持范围为：

| 客户端 | 当前可修改范围 |
| --- | --- |
| ZCode | 部分用户级 Skill、已配置或已安装插件，以及独立 MCP 的启停 |
| Codex | 独立用户级 MCP 按实验性支持开放，不要求版本验证；用户配置根 Skill 覆盖和本地市场插件，仅限已检查为 **Codex CLI 0.159.2 / Windows** 的实例 |
| Claude Code | 部分用户级插件启用状态；Skill、MCP 和项目级配置保持只读 |
| DeepSeek Harness | 部分用户级 `cordis.patch.yaml` 插件行的 `disabled` 开关；项目级条目、管理器必需组件和插件附带 MCP 保持只读 |

具体是否可写还取决于配置结构、来源、版本证据和实例权限。普通开关会创建计划并立即应用；“预览修改”可先查看差异，再手动确认。配置操作记录中成功操作可“恢复此修改”，仍先进入恢复预览并由用户确认，不会直接覆盖配置。

服务端在应用时重新检查写入许可、目标位置和配置摘要。实例改为只读后，旧计划不能继续写入；外部配置变化可能使计划冲突，需要重新扫描和准备。隔离演示配置与真实客户端配置分开。

## 扫描与读取限额

以下自定义来源扫描限额不代表所有客户端适配器都采用相同扫描规则；以对应来源的报告为准。

| 场景 | 当前限额 |
| --- | --- |
| 自定义来源深度 | 快速：入口及直接子目录；深度：最多 8 层 |
| 自定义来源遍历 | 每次最多 500 个目录，每目录最多 2,000 个直接子项 |
| manifest / frontmatter | 单个 manifest 最多 2 MiB，YAML frontmatter 最多 128 KiB |
| 详情辅助信息 | `agents/openai.yaml` 最多 128 KiB；支持文件清单最多 80 个文件，最多遍历 100 个目录、深度 3，每目录最多 2,000 项 |
| 正文展示 | 详情正文最多 1,000,000 字符；对比返回的每侧正文最多 20,000 字符 |
| 内容搜索 | 每页检查最多 30 条候选，manifest 累计读取预算 24 MiB；返回后续位置、失败数和范围信息 |
| 当前文件可用性检查 | 每次合计最多检查 80 条绑定/独立记录，manifest 累计读取预算 24 MiB；截断会明确提示 |
| 收藏与命名筛选 | 最多 500 个收藏、30 个命名筛选 |

达到限额时，不应把当前报告当作完整资源清单。可以登记更具体的目录、使用有效的续扫入口，或继续加载搜索后续页；“强制完整扫描”不会取消这些限额。

## 开发运行

```sh
pnpm install --frozen-lockfile
pnpm dev
```

开发模式默认启动 API `127.0.0.1:4780` 和 Vite 页面 `127.0.0.1:5173`。请打开终端打印的 **`Vite UI` 完整票据链接**；仅打开没有票据的基础地址不会自动建立新会话。票据是一次性的，不能反复兑换。

未设置 home 覆盖变量时，开发模式使用隔离扫描目录 `work/dev-data/home`，应用数据位于 `work/dev-data`。可用 `AGENTDECK_DEV_HOME` 更换开发扫描 home；“发现客户端”是显式读取实际用户配置的入口。演示目录默认在 `work/demo`；设置 `AGENTDECK_HOME` 时使用其下的 `demo`。不要将开发夹具、演示写入或测试操作指向真实用户配置目录。

Vite 的 `/api` 和 `/health` 代理当前固定指向 `127.0.0.1:4780`。如果修改开发 API 的 `PORT`，需同步调整 `apps/web/vite.config.ts` 的代理目标；开发模式不能仅设置 `PORT=0` 就让前端自动找到新端口。

## 数据与环境变量

| 变量 | 用途 |
| --- | --- |
| `AGENTDECK_HOME` | 应用数据目录，包含 SQLite 数据库、偏好、来源登记、监听开关、变化记录、计划和备份/恢复数据 |
| `USER_HOME` / `AGENTDECK_USER_HOME` | 扫描用户 home 的覆盖值；常规扫描优先使用 `USER_HOME`，其次 `AGENTDECK_USER_HOME` |
| `AGENTDECK_DEV_HOME` | 未被上述 home 变量覆盖时，指定开发扫描 home |
| `CODEX_HOME` / `ZCODE_HOME` / `CLAUDE_CONFIG_DIR` / `DSH_HOME` | 对应客户端的配置根覆盖值；开发默认发现环境保持隔离 |
| `PORT` | 服务端口；终端入口默认 `4780`，一键启动未设置时使用 `0` 自动分配 |
| `AGENTDECK_OPEN_BROWSER` | 设为 `1` 时 `pnpm start` 自动打开浏览器；一键脚本默认开启 |
| `AGENTDECK_BROWSER_PATH` | 指定浏览器测试使用的浏览器可执行文件 |

未设置 `AGENTDECK_HOME` 时，生产数据默认位置如下：

- Windows：`%LOCALAPPDATA%\AgentDeck`。
- macOS：`~/Library/Application Support/AgentDeck`。
- Linux：`$XDG_DATA_HOME/agentdeck`，未设置时为 `~/.local/share/agentdeck`。

实例会持久化关联的用户 home，配置根和 home 可以分开存放；重新发现会刷新关联，重启后重扫沿用已保存的 home。旧索引缺少关联时使用服务配置的扫描 home，可重新发现补齐。

计划和备份可能包含原始配置字节及敏感信息，并以明文保存在应用数据目录。程序不负责加密数据或配置专用文件 ACL，请将该目录放在仅可信用户可访问的位置。

## 常见问题

### 启动出现 `EACCES` 或 `EADDRINUSE`

`EADDRINUSE` 通常表示端口已占用；Windows 的 `EACCES` 也可能来自系统保留端口，不一定是已有 AgentDeck 进程。优先使用双击启动的自动端口，或在运行 `pnpm start` 前设置 `$env:PORT = '0'`。如果双击仍使用固定端口，请检查是否预先设置了 `PORT`。

### 更新后提示旧索引、物理路径证据缺失或目录已变化

先核对实际路径，再重扫已登记实例、项目和相关自定义来源。目录被移动或替换为链接后，详情、对比和打开目录可能被拒绝；需要显式重扫补齐证据。监听不会自动授权新根，可在核对并重扫后关闭、重新开启。

### Skill 没有出现，或搜索没有命中

查看来源是否扫描完整、格式候选和跳过原因；快速扫描可能没有达到嵌套目录。使用深度扫描或登记更具体的目录。内容搜索需继续加载尚未检查的候选页；自定义来源和客户端绑定是不同清单，独立目录被发现不代表已安装到客户端。

## API 概览

API 前缀为 `/api/v1`。除 `/health` 和一次性会话引导接口外，API 需要本机会话；写入及其他非 GET 操作受 CSRF token 保护。服务只监听回环地址，拒绝非本机连接，不开放通用 CORS。

| 方法 | 路由 | 用途 |
| --- | --- | --- |
| `GET` | `/health` | 本机服务状态和版本 |
| `GET` | `/api/v1/adapters`、`/api/v1/catalog` | 适配器能力、资源目录和扫描变化记录 |
| `GET` | `/api/v1/skills/details` | Skill 详情，参数为 `bindingId`，或 `sourceId` + `findingPath` |
| `GET` | `/api/v1/skills/availability` | 当前文件与格式检查；必需 `instanceId`，可带 `projectId`、`workdir` |
| `GET` | `/api/v1/skills/search?q=...&offset=0` | 搜索 Skill 名称、说明、作者、依赖和正文；使用 `nextOffset` 继续查询 |
| `GET` | `/api/v1/compatibility` | 客户端识别和能力证据 |
| `POST` | `/api/v1/instances`、`/api/v1/projects` | 登记客户端实例或项目 |
| `POST` | `/api/v1/scans` | 发现或扫描已登记客户端/项目资源 |
| `POST` | `/api/v1/skill-sources` | 添加并扫描自定义 Skill 目录，包含 `path`、`mode`、`followLinks` |
| `POST` | `/api/v1/skill-sources/:id/scan` | 重扫，正文可为 `{ "force": true }` 以绕过解析缓存 |
| `PUT` | `/api/v1/skill-sources/:id/watch` | 设置监听，正文为 `{ "enabled": true }` 或 `{ "enabled": false }` |
| `DELETE` | `/api/v1/skill-sources/:id` | 取消入口登记，不删除原目录 |
| `GET`、`PUT` | `/api/v1/resource-preferences` | 读取或保存完整的 `favorites`、`savedFilters` 与 `display`（内置/仅缓存显示策略）偏好对象 |
| `POST` | `/api/v1/skills/compare` | 用 `left`、`right` 两个已发现资源引用对比 Skill |
| `POST` | `/api/v1/resources/open-directory` | 打开一个已登记资源引用所在目录 |
| `POST` | `/api/v1/instances/:id/version-check` | 主动检查客户端版本 |
| `POST` | `/api/v1/demo` | 创建或刷新隔离演示目录 |
| `POST` | `/api/v1/plans`、`/api/v1/plans/:id/apply` | 创建和应用单项变更计划 |
| `GET` | `/api/v1/operations` | 查询操作记录 |
| `POST` | `/api/v1/operations/:id/restore-plan` | 基于备份准备恢复计划 |
| `GET` | `/api/v1/events` | 接收目录和操作更新事件（SSE） |

打开目录和对比使用的资源引用，与详情接口的查询参数不同：

```json
{ "kind": "binding", "bindingId": "<binding-id>" }
```

```json
{ "kind": "source", "sourceId": "<source-id>", "findingPath": "<已扫描的 SKILL.md 路径>" }
```

这些接口不接受任意路径或 shell 命令。目录 API 返回结构化元数据；Skill 详情、搜索和对比会返回受限的说明/正文，不提供原始客户端配置文档下载。

客户端扫描接口返回的目录包含 `lastScan`：状态为 `succeeded`、`partial` 或 `failed`，记录完成时间、成功扫描数及失败来源。`lastScanAt` 仅在整次请求（包括发现和已登记项目扫描）成功时更新。失败仍可能返回保留的目录和 HTTP 200，应检查 `lastScan.status`；自定义入口则检查其独立 `report.status` 和扫描时间。

页面的“刷新当前页面数据”（顶栏）读取已有目录等当前页数据，不重新遍历磁盘；“扫描客户端”“发现客户端”、项目行“扫描项目”和来源“重新扫描”才重新读取文件。短时间 SSE 事件合并，刷新串行并保留待刷新标记；事件更新只取目录，显式刷新才重新获取适配器、兼容性和偏好。非首屏页面、详情与 Markdown 依赖按需加载。项目扫描结束后在项目行显示结果并提供“查看资源”入口，不会自动切换页面或清空筛选。

## 开发检查

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:e2e
```

浏览器测试运行构建后的服务，需先执行 `pnpm build`。默认查找本机 Edge 或 Chrome，也可通过 `AGENTDECK_BROWSER_PATH` 指定可执行文件。报告、截图、临时数据和兼容性证据写入被 Git 忽略的 `work/`。

常规检查使用隔离夹具。原生 Codex 验收默认跳过，需显式设置 `AGENTDECK_VERIFY_NATIVE_CODEX=1` 和 `AGENTDECK_CODEX_PATH`；读取真实客户端来源的浏览器验收需显式设置 `AGENTDECK_VERIFY_REAL_CLIENTS=1`，不要将其当作默认隔离测试的一部分。

Codex 原生验收覆盖 Windows / CLI 0.159.2 下，隔离配置根中的独立用户级 STDIO MCP、配置根 Skill 和本地市场插件配置复读与恢复；它不代表所有版本、平台或运行中会话都已验证。

## 项目结构与文档

- `apps/web`：Vue Web 界面、筛选、详情、可用性和日常操作。
