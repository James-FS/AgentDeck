# AgentDeck 首轮实施决策

日期：2026-10-02。项目目录 D:/Code/AgentDeck。此文件约束首轮代码，完整产品范围见实施方案.md。

## 交付范围

首轮交付可启动的 Vue 3 本地网页、Fastify API、SQLite 持久化、四客户端可扩展只读扫描、Skill 三维筛选、手动实例/项目登记、扫描与诊断信息、以及仅针对明确注册且允许写入的 Codex 用户配置的独立 MCP 计划/应用/恢复链路。真实默认发现的实例默认只读；写入目标需在登记时明确 opt-in 并通过支持结构检查。本轮不声称已经验证全部客户端版本，不实现客户端运行/任务调度、安装更新、账号登录或通用配置编辑。

开发与测试数据默认在 work/dev-data，样例配置在 work/demo；不改用户真实 Agent 配置。允许 UI 读取用户主动登记或扫描发现的配置来源，只返回结构化脱敏元数据；不向 UI 返回原始配置凭据。浏览器只连接本机服务；生产网页和 API 同源，开发由 Vite 代理。

本机 Node 为 24.7.0，pnpm 为 11.22.0。首轮固定 Node >=22.12 兼容工具链，Vite 7（7.3.1 的 npm engines 为 ^20.19.0 || >=22.12.0）；锁定具体依赖和 pnpm-lock.yaml。SQLite 首选方案中的 better-sqlite3；若本机二进制构建受阻，决定采用 Node 24 的 node:sqlite 并明确其稳定性/版本限制，不可悄悄退回 JSON 假冒 SQLite。

## 协作分工

- 实现代理 backend：根工程、contracts、core 应用服务、storage、server、CLI、README。唯一依赖安装负责者。
- 实现代理 adapters：packages/adapters、packages/change-engine、配置编辑、发现与扫描、Codex MCP 修改及恢复。
- 实现代理 frontend：apps/web 的 Vue 界面、Vite配置和前端 package.json。
- 主代理：架构决策、跨模块审查、fixtures与测试、实机运行验证、文档完成状态。

## 公共类型（由 backend 在 packages/contracts/src/index.ts 实现）

公共包名称 @agentdeck/contracts。所有 Node 后端包使用 TypeScript/ESM，由 tsx 开发执行，tsup/tsc 或经过验证的构建流程发布。后端不要假定工作区 TypeScript 直接可被生产 Node 导入。前端 import type 可使用工作区源，API 响应需实际校验。

- AgentId = codex | claude-code | zcode | deepseek-harness（对外注册表用 string，允许未来扩展）。
- ResourceKind = skill | plugin | mcp。
- SkillScope = user-global | project | project-directory | native；会话范围仅未来保留。
- SourceKind = user | repository | plugin | builtin | organization | account-sync | unknown。
- CompatibilityClass = portable | agent-specific | conditional | unknown。
- AgentInstance：id, agentId, name, configRoot, version: string|null, executable: string|null, discovery: auto|manual|demo, writable:boolean, checkedAt, diagnostics:string[]。
- Project：id,name,rootPath。
- Binding：id,resourceId,instanceId,projectId:string|null,kind,name,description,scope,sourceKind,compatibilityClass,parentId:string|null,sourcePath,nativeKey,enabled:boolean|null,runtime:unknown|pending|active|inactive,writable:boolean,readOnlyReason:string|null,diagnostics:string[],updatedAt。
- Catalog：instances,projects,bindings,lastScanAt:string|null。
- AdapterInfo：id,name,description,supportedKinds,writeSupport:string[]。
- ScanContext：instance,project?:Project；只读扫描，不执行表达式、插件、Skill、MCP或模型调用。
- ScanReport：bindings,diagnostics:string[]。
- ChangeRequest：bindingId,enabled:boolean。
- ChangePlan：id,instanceId,bindingId,action:toggle|restore,targetPath,beforeHash,afterHash,diff（脱敏）,desiredEnabled:boolean|null,createdAt,expiresAt,restoreOf?:string,status:ready|applied|expired；实际原文只在受保护的服务端持久层保存，不放DTO。
- Operation：id,planId,status:succeeded|failed|conflict,kind:toggle|restore,targetPath,createdAt,error:string|null,backupId:string|null。
- ApiError：error:{code,message,requestId?}。

界面可读状态 enabled 仅表示配置状态；所有 runtime 无证据保持 unknown，配置写入后为 pending。分类 unknown 优于猜测通用。来源与 scope 分开。

## 适配器与变更实现出口

adapters 包提供 createAdapterRegistry(): AgentAdapter[]，每个适配器 id/name/info、discover({homeDir,env}): Promise<AgentInstance[]>、scan(context): Promise<ScanReport>。实例绑定ID用可重复的摘要，不随机生成导致扫描抖动。register插件采用注册表，前端从 API 获取，不硬编码客户端枚举。

目录建议支持：Codex 用户 .agents/skills 与 CODEX_HOME 下兼容skills和plugins、config.toml；Claude 配置根skills/plugins、用户 .claude.json 与项目 .mcp.json、settings.json/settings.local.json；官方 ZCode cli/config.json、其清单声明技能、独立skills候选；DSH skills/profile及声明patch。每次只扫描有限范围，读取失败返回诊断，不宣称支持所有布局。共享路径、同名、未知版本和DSH动态表达式保持显式边界。

change-engine 提供面向独立Codex MCP的函数：prepareToggle({configPath,serverName,enabled}) 返回原文、修改后原文、摘要、脱敏diff；applyPrepared(...) 检查过期、原文摘要、路径身份并执行备份+原子替换；prepareRestore(...) 使用实际写后摘要避免覆盖外部修改。具体跨模块函数签名由adapters先发backend确认，并在本文件补充。支持普通显式 [mcp_servers.NAME] 或带引号名称的表；不支持结构拒绝而非全文件重写。保留换行、BOM、注释和未知字段；现有 enabled 定点修改或缺失时在明确表中插入。仅允许一个目标表，重复/inline/不明确结构拒绝，解析前后用TOML解析器复核；绝不写插件MCP。

写入资格需要：手动实例 writable=true、Codex独立MCP且明确用户配置文件、语法支持、可验证前置摘要；自动发现实例只读。版本未知必须以显式 experimental 写入能力标注，不宣称实机兼容。服务端验证binding belongs to instance，不能接受前端任意文件路径。所有写入在一个队列里串行，使用journal与快照保证可恢复；原始快照目录权限当前用户；恢复不删除未知文件。

## API

成功JSON直接返回DTO；所有错误统一ApiError。接口：GET /health；GET /api/v1/adapters；GET /api/v1/catalog；POST /api/v1/instances {agentId,name?,configRoot,writable?:boolean}；POST /api/v1/projects {name?,rootPath}；POST /api/v1/scans {discover?:boolean,instanceId?:string,projectId?:string}，本轮可同步完成，返回Catalog；POST /api/v1/demo 初始化隔离样例（幂等），返回Catalog；POST /api/v1/plans {bindingId,enabled}；POST /api/v1/plans/:id/apply {digest:afterHash}；GET /api/v1/operations；POST /api/v1/operations/:id/restore-plan 返回ChangePlan；GET /api/v1/events SSE catalog.changed/operation.completed。

原始计划、备份不可由浏览器路径读取。首轮仅loopback、Host/Origin验证、启动票据换HttpOnly sameSite=strict cookie+CSRF。推荐 GET /api/v1/session 返回csrfToken（有会话）；POST /api/v1/session/bootstrap {ticket} 一次性票据兑换；serve打印浏览器URL包含 #ticket=，UI兑换并移除fragment。开发模式可由Vite服务器提供服务端同源bootstrap重定向，不能在前端bundle硬编码固定token。若开发引导未完成，用backend打印URL后在Vite相应URL携带ticket，README明确。

UI API client credentials=same-origin，修改请求 X-CSRF-Token。首页加载 /session；无cookie时显示连接说明，不能把未授权错误伪装为空资源。开发Vite proxy /api 和 /health。SSE用同源cookie；不要记录ticket、原始凭据或原始配置。
