## 1. 任务与交付目标

本轮解决资源管理页面中内置资源混入、重复记录聚合不一致、多层展开和列表信息拥挤的问题。

用户期望：日常首先看到自己需要管理的资源，Agent 自带资源默认不显示；同一个资源的多个发现记录集中展示，配置状态和操作仍能准确定位到具体 Agent、实例和项目。

执行 AI 应直接完成分析、实现、自检与验收。本文已明确的正常实现步骤无需逐步请求用户确认。遇到无法从源码或本文消除的重大冲突时，先完成不受影响的部分，再说明具体决策点。

交付内容：

1. 默认隐藏有可靠证据的 Agent 内置资源，以及没有安装或配置关联的纯缓存记录。
2. 统一资源展示模型，聚合同一物理来源的客户端绑定与独立发现，保留原始引用。
3. Skill、插件、MCP 类型视图语义清楚，查找 Skill 不必展开插件版本树。
4. 精简资源表格，将完整路径、证据、版本和绑定明细放入详情。
5. 搜索、收藏、筛选、计数、分页和配置操作与新展示模型一致。
6. 更新 README，新增实际验收记录，列明测试结果和限制。

## 3. 已核实的现状

1. sourceKind 已包含 builtin；Codex 的 skills/.system 已按此来源扫描，ZCode 和 DeepSeek 的部分随包资源也有专门来源识别。
2. 默认 sourceFilter 为空，页面没有内置资源默认隐藏策略。
3. Agent 全局目录归类表示存放或配置归属，不代表资源由 Agent 自带。用户添加到 .codex/skills 的资源也可能属于 agent-global。
4. Codex 插件缓存记录通常标记为 plugin；仅过滤 builtin 不能保证识别所有客户端随包资源，也不能据此把所有官方插件隐藏。
5. 现有公共资源分组主要针对用户级 .agents 目录，插件按实例、项目和插件身份分组，MCP 按服务证据分组，三者含义不同。
6. 独立 Skill 扫描结果与绑定记录使用不同展示分支，同一物理 Skill 被两条路径发现时没有统一聚合。
7. Skill 类型筛选仍可能输出插件父行，展开后才能看到 Skill。
8. 类型计数、统计卡、表格和独立发现使用了不同计算路径，不能直接把当前数字当作统一去重数量。
9. 收藏、对比和配置操作依赖真实资源引用；不能用展示分组 ID 直接替代 bindingId。

上述结论是制定计划时的源码状态。执行时重新核对必要差异，不把历史验收记录当作本轮测试结果。

## 4. 范围与基本约束

- 沿用 Vue、Pinia、Element Plus、Fastify 和现有 TypeScript monorepo。
- 保留资源库、来源与扫描、项目可用性、变化记录四个现有页面入口。
- 保留顶栏唯一的客户端和项目上下文；具体项目包含用户级绑定。独立来源仍只在全部上下文展示，不自动推测其客户端或项目绑定。
- 保留绿色品牌色、浅色界面和现有键盘可访问性。
- 筛选继续直接平铺、空间不足时换行，不重新引入“更多筛选”折叠开关。这是已有用户偏好。
- 仅调整索引证据、展示及应用自身偏好；不自动安装、移动、同步、删除或执行资源。
- 隐藏不等于删除索引、禁用配置或关闭监听；隐藏资源的变化和诊断仍可在对应入口查到。
- 不扩大客户端配置写入权限，不合并多个绑定的开关，不从名称推断加载状态。
- 保留目录授权、物理路径验证、链接边界、读取预算、Markdown 安全、配置摘要复核和偏好并发保护。
- 不增加自动去重清理、市场安装、云同步、新客户端适配器或运行进程探测。

## 5. 产品规则

### 5.1 默认显示与偏好

资源库默认使用“我的资源”显示策略。它是资源库内部的显示预设，不新增第五个顶层页签。

常驻两个明确的复选框或开关：

- 显示 Agent 内置资源：新用户默认关闭。
- 显示仅缓存资源：新用户默认关闭。

显示策略：

| 资源情况 | 默认行为 |
| --- | --- |
| 用户自建、导入、项目提供、独立登记 | 显示 |
| 有安装或配置关联的插件及其资源 | 显示；若有可靠内置证据，受内置开关控制 |
| 明确禁用的用户配置或已安装资源 | 显示，保留禁用状态 |
| 有可靠证据的 Agent 内置资源 | 隐藏 |
| 没有安装或配置关联、仅从缓存发现的资源 | 隐藏 |
| 来源或安装证据不足 | 保守显示并标注待确认，不能误判为内置 |

两个开关独立判断；同时满足内置和仅缓存条件时，必须同时允许这两类记录才能显示对应记录。

显示简短说明，例如“当前范围隐藏：内置 24 项、仅缓存 16 项”。两项可能重叠，文案不得暗示可以直接相加。可点击对应项开启显示。数字为示例，实际由当前上下文计算。

偏好保存在 AgentDeck 自身数据库，刷新和服务重启后保持。清空普通筛选保留这两个开关，不恢复成显示全部。

命名筛选应保存这两个值；旧命名筛选缺少字段时使用默认关闭，并可正常读取。显式选择来源为“Agent 内置”时，自动开启“显示 Agent 内置资源”，同步更新控件；取消来源条件不自动关闭开关。

“只看收藏”仍遵循显示策略。若收藏项被隐藏，给出可发现的提示与显示入口，不显示成已失效。

### 5.2 内置来源的判断

优先复用 sourceKind、builtinSourcePath 和适配器已验证的随包来源证据。

不得单凭以下信息判断内置：

- 位于 .codex、.claude、.zcode 等配置目录。
- classification.category 为 agent-global 或 agent-project。
- 插件来自官方市场、名称带 openai 或属于官方作者。
- 资源处于 cache、只读或启用状态未知。

插件子资源可以继承父插件已验证的内置来源。对适配器尚未识别的随包来源，只有在拿到受限扫描范围内的可靠证据并补充测试后才新增识别；不把路径字符串猜测包装为已验证事实。

独立发现目前缺少完整来源分类。与已验证绑定确认为同一物理资源时可关联其来源证据；否则保持独立来源待确认，不擅自认定用户主动安装或 Agent 内置。

### 5.3 仅缓存的判断

origin 为 cache 是判断起点，不是充分条件。需同时检查明确的配置引用、适配器接受的安装记录，以及父插件的关联证据。

明确禁用的配置仍属于配置关联，不能按纯缓存隐藏。安装证据只使用适配器认可的字段，不从 enabled=true 或目录存在反推安装。

已有关联的插件可显示其逻辑插件行，但不得把所有历史缓存版本宣称为已安装或当前使用。历史版本进入详情，当前版本缺少证据时继续标注未确认。

### 5.4 资源身份与聚合

引入统一的只读展示实体，关联一个或多个真实绑定、独立发现和发现入口。可以新增专门模块，不把聚合逻辑继续堆入 ResourcesPage.vue。

建议每个实体包含稳定展示键、类型、名称、摘要、来源摘要、绑定引用、独立发现引用、证据、版本和状态汇总。具体类型名由实现决定。

身份规则：

| 场景 | 规则 |
| --- | --- |
| 同一物理 Skill、多 Agent 或多入口发现 | 聚合为一行，保留所有关联记录 |
| 独立来源与客户端绑定指向同一 Skill | 聚合展示，独立发现仍不变成可写绑定 |
| 同名不同目录的 Skill | 保留不同资源，标记同名关系并提供对比 |
| 不同路径但 SKILL.md 内容相同 | 可标记“说明文件相同”，不自动合并物理副本 |
| 同一插件的配置与缓存版本 | 逻辑插件一行，版本和配置记录进入详情 |
| 同一 MCP 服务的多个配置 | 保留服务分组，详情逐条显示配置差异与控制目标 |

Skill 聚合需统一“Skill 目录”和“SKILL.md 文件”这两种路径口径，基于受信任扫描证据对应到规范物理 manifest 或物理 Skill 根；Windows 大小写和链接处理遵守现有平台及边界规则。

缺少可靠物理身份的旧索引保持分开并提示重扫，不靠名称、逻辑路径近似或内容摘要强行合并。不在浏览器自行探测文件系统。

插件继续保留实例、项目、市场及已验证插件身份边界，不因同名跨实例合并。MCP 复用已有服务入口证据与私密配置差异比较，不公开敏感配置，不宣称共用运行进程。

一个资源同时存在独立登记和客户端发现时，新增入口不能使它重复，也不能仅因入口名为“独立来源”就绕过已有可靠内置证据。来源证据相互矛盾时保守显示、保留诊断，避免隐藏用户资源。

### 5.5 类型视图和行结构

- Skill 视图直接展示 Skill 实体；插件附带 Skill 标注“来自某插件”，名称直接打开 Skill 阅读详情。
- 插件视图直接展示逻辑插件；详情包含内容清单、绑定、版本和缓存证据。
- MCP 视图直接展示服务或未能聚合的 MCP 条目；详情显示配置绑定。
- 全部视图平铺展示这三类资源实体，不再混入缓存版本行和配置记录行。同一个实体在列表中只出现一次。
- 插件包与其中的 Skill、MCP 属于不同类型实体，可以分别出现；使用类型和“来自某插件”表达关系，不称为重复资源。
- 版本、配置和发现记录放入详情内的分区，不再要求用户在主表逐层展开才能找到目标 Skill。
- 搜索命中子 Skill 时直接显示 Skill，不能只显示没有匹配内容的插件父行。

主表优先保留五列：资源名称与简述、来源、关联 Agent / 项目、状态、操作。

名称区域包含收藏、类型和必要关系标签；描述限制行数。完整路径、分类理由、扫描证据、只读原因、历史版本和多入口明细放入详情。有异常时提供简短状态和详情入口。

单一真实绑定且现有权限允许时，可以保留直接开关。多绑定实体显示“管理绑定”，在详情中逐条操作，不提供汇总开关。

### 5.6 状态、搜索、收藏与对比

聚合状态用数量表达，例如“2 项启用 · 1 项禁用 · 1 项未确认”。计算对象是去重后的真实绑定，不把发现入口当作配置绑定。

现有公共 .agents 资源的默认启用展示约定继续保留，但需与各 Agent 的实际配置绑定状态分开表达。不能把所有绑定的已禁用记录覆盖为启用，也不能暗示实际会话加载。

纯独立资源显示“独立发现 / 未绑定”；格式异常继续可见并可查看详情。文件检查、扫描时配置与实际加载仍采用原有不同语义。

搜索遵循当前上下文、显示策略、类型和筛选交集。隐藏资源不得通过正文匹配重新出现；保留“包含隐藏资源搜索”的明确入口，该入口应开启对应显示开关并体现到界面。

内容搜索继续使用防抖、请求序号或取消、候选分页和预算限制。命中同一实体的多条记录合并展示，保留命中片段和来源说明；服务端尚未查完时不得宣称没有结果。

收藏保留真实引用并兼容旧数据。实体只要有合法关联引用被收藏，就显示已收藏；点击取消时清理该实体当前已知关联引用的收藏，不能刚取消就因另一个引用又显示已收藏。新增收藏使用确定、稳定的真实引用，不擅自把独立收藏迁移成另一个绑定。

资源被筛选或隐藏不等于收藏失效。新扫描导致引用失效时，保留既有失效提示，不按名称重定向。

对比仍只接受两个合法 Skill 引用；同一物理 Skill 的两个入口不能伪装成两个不同副本。不同目录的同名或同内容副本仍可比较。保留对比选择跨分页、筛选、页签和失效处理。

### 5.7 计数与分页

使用同一展示实体集合派生表格、统计卡、类型计数和分页，禁止各处分头追加独立发现数量。

- 统计卡：当前上下文和显示策略下的唯一资源数；不受搜索、收藏及其他普通筛选影响，文案说明口径。
- 类型计数：与统计卡同一基础集合，按 Skill、插件、MCP 分类。全部数量等于三类之和。
- 结果区：当前筛选匹配 X 个资源、关联 Y 条配置绑定；X 不含版本行或发现入口。
- 实际页面：显示本页范围和匹配总量，避免把 50 行分页描述为已经显示全部。
- 隐藏数量：在当前上下文、普通筛选前，计算各显示开关排除的唯一实体；重叠原因不相加。实体仍有可显示记录时，不计为整个实体隐藏。

上下文限制、来源可见性和记录筛选必须先作用于关联记录，再派生行和状态汇总；同时可保留受上下文限制后的完整关联供详情查看，明确“当前匹配”和“其他关联”。隐藏记录不能进入代表行、状态汇总、快捷操作或搜索片段。

默认继续每页 50 个资源实体。展示键必须稳定，刷新、筛选和代表绑定顺序改变时，不随机改变收藏、打开详情或选中对比的目标。

## 6. 分阶段实施

### A：显示策略和来源证据

1. 核对内置、配置、安装与缓存证据，提取可复用的纯判断函数。
2. 增加两个持久化显示偏好、旧数据默认值和命名筛选兼容。
3. 接入默认隐藏、隐藏数量、空结果引导、显式内置筛选联动。
4. 核查子资源继承、独立发现和搜索不会使内置资源重新出现。
5. 如调整共享契约，完整同步 Zod、API、存储读写及测试，不只修改 TypeScript 接口。

阶段完成标准：新用户默认隐藏可靠内置和纯缓存；用户添加到 Agent 目录的资源、禁用配置及已安装资源不被误隐藏；偏好刷新和重启保持。

### B：统一实体和身份聚合

1. 建立统一的只读实体派生模块，分离 Skill 物理来源、插件逻辑身份和 MCP 服务身份规则。
2. 将独立发现与绑定纳入同一管线，统一路径口径和多入口关联。
3. 接入类型视图、搜索映射和聚合后的稳定分页。
4. 处理同名不同来源、同内容副本、旧索引、证据缺失和资源失效。
5. 同步收藏、对比和已打开详情的刷新行为。

阶段完成标准：同一物理 Skill 在同一上下文只出现一行，保留全部合法关联；不同副本不误合并；Skill 类型视图可直接阅读插件附带 Skill。

### C：表格、详情、操作和计数

1. 精简五列表格，保留所有平铺筛选、键盘入口及窄窗口操作。

## 7. 验收测试矩阵

优先扩展现有测试，并为新的纯实体派生逻辑增加有意义的单元测试。浏览器测试使用隔离夹具，不修改真实用户 Agent 配置，不启动真实 Skill 或 MCP。

| 场景 | 必须结果 |
| --- | --- |
| 新用户同时存在内置、用户、项目与独立资源 | 默认隐藏可靠内置，其余按上下文显示 |
| 用户 Skill 位于 .codex/skills | 不能因 Agent 全局归类而隐藏 |
| 用户主动安装官方插件 | 无内置证据时正常显示 |
| 缓存插件没有安装和配置关联 | 默认隐藏；开启缓存显示后可查看 |
| 禁用配置、有效安装记录、仅历史缓存版本 | 前两者保留，历史版本进入详情，当前版本未确认时明确提示 |
| 内置插件附带 Skill 和 MCP | 默认不能通过子资源或正文搜索漏出 |
| 独立扫描与绑定指向同一物理内置 Skill | 不重复、不通过独立入口绕过隐藏 |
| 来源未知或旧索引没有身份 | 保守显示、提示重扫，不按名称合并或隐藏 |
| 同一物理 Skill 被多个 Agent 和重叠入口发现 | 一个实体，多条合法关联，刷新后展示键稳定 |
| 同名不同目录、相同 manifest 不同支持文件 | 保留不同副本，不宣称整个包一致 |
| 插件版本身份冲突、市场或项目不同 | 不能误合并或选择错误操作目标 |
| MCP 同入口但参数或状态不同 | 服务可聚合，差异和每条配置保留 |
| Skill 筛选或搜索命中插件子项 | 直接出现 Skill 阅读入口，不要求展开父插件 |
| 收藏在非代表绑定或独立发现上 | 聚合行正常显示收藏；取消后状态一致；旧偏好仍有效 |
| 收藏资源被隐藏、筛选或真正失效 | 三种情况区分清楚，不按名称跳转 |
| 对比选择跨分页、过滤、刷新和资源移除 | 原引用语义保持，失效可移除，同物理入口不伪装成两个副本 |
| 多绑定一条启用一条禁用 | 展示数量摘要，开关分别定位，不能批量改变其他绑定 |
| 公共 .agents 默认启用约定 | 默认展示约定与各绑定禁用记录均保留 |
| 上下文切换到具体客户端或项目 | 独立来源不被自动视作已绑定，旧可用性检查继续按现有规则清除 |
| 清空筛选、应用旧命名筛选、刷新及重启 | 显示偏好符合本文规则，默认值和持久化一致 |
| 两个隐藏原因重叠或实体部分记录被隐藏 | 计数无误、无双算总量、隐藏记录不进入状态或操作 |
| 搜索仍有未检查候选、请求乱序 | 继续查询有效，旧结果不覆盖新上下文 |
| 100 和 1,000 条隔离资源记录 | 分页、搜索和切换流畅，无明显回退，不以几条演示数据代替规模检查 |
| 约 1366×768 与 1920×1080 窗口 | 名称、状态和核心操作可用，筛选换行，完整路径在详情可读 |

最终执行并记录：

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:e2e
git -c core.whitespace=cr-at-eol diff --check
```

阶段内先运行相关定向测试，最终运行完整检查。已有失败需记录是否基线问题；不得隐去失败、随意降低断言或把跳过当作通过。真实客户端 opt-in 测试不默认启用，说明未覆盖范围即可。
