# 首轮适配器与 Codex 变更引擎边界

ZCode 显示名已统一为“ZCode”。旧“Official ZCode CLI”是适配器固定标签，不是客户端识别结果。本轮依据官方文档补齐客户端缓存、项目 MCP 与公共回退，不据目录名认定用户使用 CLI，不宣称完整覆盖。新增入口、公共归属修正及证据见[适配器扫描补齐](./适配器扫描补齐.md)。下表为此前基线入口，新增入口以该记录为准。

更新：2026-10-04。历史原生版本与验收结论保留原范围。扫描器只读固定配置根和已登记项目，不启动客户端、Skill、插件或 MCP 服务。真实 Windows 用户发现可用有界 PowerShell 辅助进程只读查询 ZCode 安装登记；隔离 home 不查询真实安装。新增随包入口与摘要证据见[ZCode 内置资源识别](./ZCode内置资源识别.md)。适配器发现时只检查 PATH 可执行候选，不运行版本命令。新增显式版本检查在隔离配置根、HOME 与 cwd 中执行受支持 CLI 的 `--version`；只保存固定签名识别的版本，候选替换/删除/失败使旧证据失效。原生验收和版本检查范围见《客户端兼容与原生验收》。自动发现和登记默认允许受支持的单项开关；显式只读登记继续保留。开发验收不写真实配置。

四个适配器使用稳定路径与原生键生成实例/Binding 标识。扫描配置根及其直接子目录，目录项上限为 300；JSON/TOML 配置读取上限为 1 MiB，Skill `SKILL.md` 上限为 96 KiB，DSH 每个 profile 目录最多读取 40 个 patch 文件。扫描跳过符号链接和 Windows junction，不遍历整盘或已登记项目根以外的路径。用户级 Binding 在项目扫描时仍保持 `projectId: null`；项目资源另行登记。

| Agent | 用户配置与资源候选 | 已登记项目候选 |
|---|---|---|
| Codex | `CODEX_HOME` 或 `~/.codex`；读取 `config.toml`、`~/.agents/skills`、`<configRoot>/skills`、`skills/.system`、直接插件目录和 `plugins/cache/<marketplace>/<plugin>/<version>` | `.agents/skills`、`.codex/skills`、`.codex/config.toml` 中独立 MCP 与插件声明 |
| Claude Code | `CLAUDE_CONFIG_DIR` 或 `~/.claude`；读取 `settings.json`、`skills`、直接插件目录、`plugins/cache/<marketplace>/<plugin>/<version>`、`plugins/installed_plugins.json`，以及默认配置根的父目录中的 `.claude.json` | `.claude/skills`、`.agents/skills`、`.claude/settings.json`、`.claude/settings.local.json`、`.mcp.json` |
| ZCode | `ZCODE_HOME` 或 `~/.zcode`；读取 `cli/config.json` 的 MCP 与 `plugins.enabledPlugins`、`skills`、直接插件目录 | `.zcode/cli/config.json` 的 MCP 与插件声明、`.zcode/skills`、`skills` |
| DeepSeek Harness | `DSH_HOME` 或 `~/.dsh`；读取 `skills` 和 `profiles/<profile>/*.{yml,yaml}` 静态 patch 行 | `.dsh/skills`、`.dsh/profiles` |

这些路径是当前扫描器实现的候选布局，不表示已经通过全部客户端版本验证。本机静态来源核对见《只读扫描兼容验证》；ZCode 项目级 `skills` 候选、DSH 项目级 `.dsh` 候选和不同 `CLAUDE_CONFIG_DIR` 下的用户状态路径仍需要原生客户端运行时证据。缓存读取 `.codex-plugin/plugin.json` 或 `.claude-plugin/plugin.json`，支持包内默认或声明的 Skills 根、单 Skill 目录，以及内联或文件声明的 MCP。路径声明必须留在包内且不能经符号链接或 junction 越界；`cache`、`data`、`marketplaces` 与隐藏基础设施容器不作为插件。插件内 MCP 独立开关保持只读；Codex 本地市场插件整体控制的有限新增范围见下文。

插件缓存最多检查 300 个包、2400 个目录项；每个目录最多 300 项，声明路径最多 20 个，每个 Skills 根最多索引 100 个子项，每个 MCP 清单最多 200 个服务器。触及读取限制时保留诊断。缓存按版本保存，不把最高版本当作当前加载版本。只有完整 `name@marketplace` 身份可关联配置，manifest 名称冲突时撤销关联。当前展示配置状态与缓存存在或缺失，不展示运行状态；Claude 安装登记指向缺失缓存时仍保留条目。

项目扫描会刷新全局和所选项目条目，删除已消失的来源，同时保留其他项目索引。用户全局绑定保持 `projectId: null`，项目 MCP 与插件配置不进入用户级独立 MCP 写入链路。各配置层的声明单独展示；未验证的最终优先级不推断为运行时有效状态。

Skill 的范围来自候选目录，来源来自用户、项目或插件目录；客户端适用性评估已取消；历史兼容与运行字段保留，不作为页面分类。扫描不从 Skill 正文推断可用能力。Claude 的 `skillOverrides` 仅静态映射现存同名非插件 Skill；没有对应文件时显示只读配置 Binding，并标明名字级覆盖可能影响多个资源。

Codex MCP 扫描只把顶层 `mcp_servers.<name>` 当作独立服务器。独立服务器缺少 `enabled` 时，按 Codex 默认值显示为启用；非布尔值显示为未知并只读。`plugins.<name>.mcp_servers.<name>` 作为插件子项呈现，父插件明确停用时子项也显示停用，插件 MCP 不进入写入引擎。ZCode 静态服务器缺少 `enable` 时按官方文档默认启用；其他未确认默认状态保持 `null`。配置状态不代表运行状态。

DSH 扫描排除已知 pnpm-lock.yaml/pnpm-workspace.yaml 包管理元数据，其他 profile YAML 继续有限读取。DSH patch 按 YAML AST 静态读取根序列中的插件行。`!!js` 标签由固定解析器映射成惰性标记；扫描器不把文档转换为可执行对象，不解析或执行表达式。动态、别名或缺失的 `disabled` 保持未知；不支持的 YAML 根结构和语法错误保留诊断。

独立 MCP 客户端变更要求手动登记且明确 `writable: true` 的 Codex 实例中、语法可唯一定位的独立 MCP 表；隔离 demo 实例可在其专用 demo 根内使用相同链路。Codex CLI 0.159.2/Windows/用户级独立 STDIO MCP 已在隔离配置根通过原生启停、配置复读与恢复验收；未匹配版本、HTTP transport 和其他范围不复用该原生通过结果。报告不自动改变写入策略。TOML 编辑仅替换目标表中单行布尔 `enabled`，缺失时在该表插入；语法通过 `@iarna/toml` 解析前后校验并把 CRLF 规范化为仅供解析的视图。原始文件按字节编辑，保留 BOM、CRLF/LF、注释和无关字段。重复表、inline table、非布尔 `enabled`、无法定位结构都拒绝。

预览 diff 只列出目标表的 `enabled` 变化，不显示配置原文或秘密。apply 检查计划期限、摘要、目标路径各段的 realpath/符号链接身份，并在目标目录用独占 AgentDeck lock 协调不同数据目录的写入。恢复只在当前摘要与 apply 后摘要、路径身份均吻合时生成。任意第三方编辑器不会参与 AgentDeck lock；引擎会在替换前再次读取摘要，但不能与所有外部写入者形成共同原子锁。

恢复快照和待应用计划私有字节包含配置原文，可能含凭据；它们只保存在 AgentDeck 数据目录，不进入 Binding、诊断、API 计划 diff 或 Operation 错误。POSIX 数据目录/文件使用 `0700`/`0600`。Windows 未由本包显式创建或验证仅当前用户 ACL；数据目录的 Windows ACL 继承与部署环境设置有关，不能称为加密或当前用户独占访问。


## 初期基础版新增 Skill/插件控制

Codex CLI 0.159.2 / Windows 的隔离原生验收已确认配置根 `skills/*/SKILL.md` 的用户级 `[[skills.config]]` 路径覆盖，以及已有配置和缓存精确关联的本地市场插件 `[plugins."name@marketplace"].enabled` 整体开关。须手动明确可写并检查版本；计划生成与应用时刷新证据和权限。仅改用户 `config.toml`，不改 Skill 原文或插件缓存。插件身份操作影响全部关联版本/子组件，不推断当前加载版本。重复/inline/非法或相对路径 Skill 覆盖、项目/共享/内置/插件 Skill、远程/未知市场和未配置插件只读。

详细复现、恢复说明和原生证据见《基础版使用与验收》；配置复读不代表当前会话运行状态。新增控制不改变既有独立 MCP 的实验性 HTTP/未知传输授权及 STDIO 原生证据边界。


当前五类资源归类、安装证据、项目缓存子绑定、共享规则和已登记项目刷新见[资源分类展示与筛选](./资源分类展示与筛选.md)。缺少配置证据的缓存可确定 Agent 存放归属，同时保留使用范围未知。列表已提供启停开关；新增 ZCode 用户级布尔控制的机制、证据与只读边界见[资源启停说明](./资源启停说明.md)。
