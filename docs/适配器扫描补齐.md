# 适配器扫描补齐

更新：2026-10-04。本轮只补充静态资源盘点与分类，不执行客户端或资源、不增加其他 Agent 的配置写入能力。DSH 随包安装布局的内置来源识别（随包 Skill 与 bundle 插件清单层）见[Claude 与 DSH 内置资源识别](./Claude与DSH内置资源识别.md)。

## 已有能力与本轮缺口

四个 Agent 原本都有适配器，但覆盖深度不同。Codex 已支持配置、Skill、插件多版本缓存及子组件；Claude 已支持配置、插件缓存与安装登记；ZCode 原先主要扫描配置和直接插件目录，遗漏真实客户端缓存；DSH 原先主要扫描 profile 静态行。

| Agent | 本轮补齐 | 证据与保留边界 |
| --- | --- | --- |
| ZCode | `cli/plugins/cache/<市场>/<插件>/<版本>`、原生/兼容 manifest、Skill/MCP 子项、精确匹配的 user 安装登记 | 保留所有版本；身份、版本和实际路径匹配后才关联安装；不选定当前采用版本 |
| ZCode | 已登记项目 `.zcode/config.json`、MCP `enable`、同范围 `.agents/mcp.json` 回退 | 原生服务器配置存在时不合并回退；旧项目 `.zcode/cli/config.json` 入口仍保留 |
| Claude Code | 用户 `.claude.json.projects[项目绝对路径].mcpServers` | 仅处理已登记项目；配置原文虽在用户目录，使用范围仍为项目；保留同名多层声明 |
| DeepSeek Harness | 用户 `cordis.patch.yml/.yaml` 和静态 `insert` 插件行、静态 MCP transport | 不执行 `!!js`；不计算完整 update/remove/profile 合成及最终有效优先级 |

依据：[ZCode MCP 文档](https://www.zcode.network/en/docs/mcp-services/)、[ZCode 插件文档](https://www.zcode.network/en/docs/plugin/)、[官方 CLI 缓存说明](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/README.md)、[Claude MCP 配置范围](https://code.claude.com/docs/en/mcp)、[DSH 用户 patch 说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/mcp-memory.md)。实现仍以可读取的静态证据为准，不代表所有安装版本的完整原生行为。

## 公共来源与发现适配器

明确公共入口（用户/已登记项目 `.agents` 等）的 `classification.agentId` 为空，所属 Agent 显示“公共来源”；新增 `discoveredByAgentId` 单独记录 AgentDeck 的发现适配器。由 Codex 适配器找到公共资源，不再显示为 Codex 所属，不证明 Codex 原生客户端已加载，更不证明所有 Agent 都调用了它。筛选增加“公共来源（无 Agent 归属）”。旧索引需重扫。

Agent 专属配置/安装位置仍显示所属 Agent；这只表达配置或存放归属，不表达内容专用。共享需要同一实际来源的多 Agent 索引证据；公共位置与共享证据是不同事实。保留扫描实例、项目和每个绑定身份，不合并同名资源。
