## 客户端身份与证据

兼容报告把配置实例与实际客户端识别分开：

| 状态 | 含义 |
| --- | --- |
| `verified-client` | 显式版本查询识别到 Codex/Claude CLI 的固定输出签名，且可执行文件身份仍匹配；不证明安装包来源或 Codex 桌面版本 |
| `executable-unverified` | PATH 找到候选文件，尚无有效版本签名证据；不能据名称认定为官方客户端 |
| `configuration-only` | 有配置目录，未发现可执行文件；可能是未安装、未加入 PATH 或残留配置 |
| `not-found` | 未发现或已登记来源当前缺失；不从空列表推断所有机器均未安装 |
| `demo` | 管理器创建的隔离演示来源，不作为实际客户端安装证据 |

普通扫描和兼容报告查询不启动客户端。实例页显式版本检查只执行服务端解析的 Codex/Claude `--version`；不接受浏览器传入命令或可执行路径。ZCode/DSH 缺少已验证命令，保留候选与未知状态。

版本检查使用管理器数据目录内的隔离工作目录、HOME、USERPROFILE 和客户端配置根，不继承账号凭据变量。超时、输出限制、命令失败和未知签名只产生固定说明，不保存或返回原始 stdout/stderr。观察结果随候选路径和文件身份保存；候选替换、删除、重定向或检查失败使旧版本证据失效。旧数据库单独保存的 `version` 字符串不作为版本验收证据。

能力矩阵区分静态扫描、夹具验证、原生配置复读和运行时观察。版本、平台、资源来源或作用范围不匹配时，不复用其他版本的原生通过结果。报告只解释证据，写入许可仍由实例显式登记和资源级结构检查决定。

API：`GET /api/v1/compatibility`；`POST /api/v1/instances/:id/version-check`，请求体为 `{}`，沿用会话、CSRF 和同源保护。版本证据保存于已有实例 JSON，旧数据可继续读取。

## 原生 Codex 验收

本机 `codex --version` 返回 `codex-cli 0.159.2`。独立验收使用实际 CLI、Node.js 24.7.0 和 Windows，在仓库 `work/tests` 下创建中文与空格目录。

[官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) 描述了 `mcp_servers` 配置和 `enabled=false` 停用；[高级配置文档](https://learn.chatgpt.com/docs/config-file/config-advanced) 描述了 `CODEX_HOME` 状态目录。这些文档提供验证依据，具体通过结论来自下面实际运行的测试。

1. 以隔离 `CODEX_HOME` 执行 `codex mcp add`，登记纯合成 STDIO MCP，获取 CLI 原生配置结构。
2. 通过实际 HTTP 服务手动登记隔离配置根并允许实验性修改；扫描后创建停用计划，确认预览未写文件。
3. 应用后执行 `codex mcp get <name> --json` 和 `codex mcp list --json`，原生复读均为 `enabled: false`，transport 保持。
4. 重放应用返回同一操作；从操作记录创建恢复计划，应用后文件逐字节等于原文，原生复读回到启用。另验证显式启用计划及其即时恢复，复读回到停用并精确还原该操作前字节。
5. 分别测试计划后外部编辑、应用后外部编辑；旧计划和冲突恢复返回 409，外部编辑保留。

上述流程针对缺省 `enabled` 与显式 `enabled=true` 两种配置均通过。显式变体保留 UTF-8 BOM、CRLF、注释与未知字段。服务器命令带有启动标记脚本，测试确认脚本没有执行。未调用模型、账号登录、MCP 握手或业务工具，运行状态仍为未知。

可复现证据：`tests/native-codex.test.ts`；原生生成的纯合成夹具：`fixtures/native/codex-0.159.2/config.toml`；机器可读版本矩阵：`docs/compatibility.json`。本机摘要记录位于忽略目录 `work/compatibility-proof/native-codex.json`。两种变体各检查 78 个真实来源，前后 SHA-256 相同。

## 运行验证

普通测试不要求安装 Codex，原生测试默认跳过：

```powershell
pnpm test
```

显式原生验收：

```powershell
$env:AGENTDECK_VERIFY_NATIVE_CODEX='1'
$env:AGENTDECK_CODEX_PATH=(Get-Command codex).Source
pnpm exec vitest run tests/native-codex.test.ts
Remove-Item Env:\AGENTDECK_VERIFY_NATIVE_CODEX
Remove-Item Env:\AGENTDECK_CODEX_PATH
```

配置、cwd、环境和数据库由测试自行隔离。`AGENTDECK_CODEX_PATH` 仅为测试入口，不是网页 API 的命令参数。

构建后的隔离浏览器与本机只读验收：

```powershell
pnpm build
pnpm test:e2e
$env:AGENTDECK_VERIFY_REAL_CLIENTS='1'
pnpm exec playwright test tests/browser/real-client.spec.ts
Remove-Item Env:\AGENTDECK_VERIFY_REAL_CLIENTS
```

隔离浏览器测试使用合成 CMD 输出，验证界面和证据范围，不声称识别到实际安装。显式本机测试读取实际配置并调用隔离版本检查；实际来源摘要、目录索引和界面截图保留在忽略的 `work/` 内。
