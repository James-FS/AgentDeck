## 本机数据接入修复

首次预览默认使用开发隔离 home，且空列表的扫描未发现未登记实例，导致网页没有实际数据。现已增加资源页“发现并扫描本机资源”与空状态“扫描本机配置（只读）”入口；该动作明确读取当前用户目录，重置筛选，发现实例并建立只读索引。默认开发扫描和测试仍使用隔离目录。

上一轮补齐 Codex `skills/.system` 的内置 Skill 来源，并排除 `plugins/cache` 与隐藏基础设施目录，避免将容器误算为插件。本轮继续在缓存容器内按市场、插件、版本索引实际包及其 Skills/MCP，缓存容器本身不作为插件。

上一轮本机只读扫描索引 33 条绑定（Skill 11、插件 20、MCP 2）。补齐缓存包、Claude 缓存缺失登记和 ZCode 插件配置后，本机索引为 79 条绑定（Skill 47、插件条目 27、MCP 5）。独立核对 16 个缓存插件 manifest、36 个缓存 Skill 与 MCP 声明，78 个来源文件前后摘要一致。索引数不代表全部未知布局或运行中的扩展数量。实际目录、资源索引和配置摘要仅留在忽略的 `work/` 下，证据范围见《只读扫描兼容验证》。

继续开发后类型检查、lint、构建与 54 项自动化回归通过；隔离浏览器 2 项和显式真实只读浏览器 1 项通过。覆盖缓存列表与筛选清空、插件版本及配置证据详情、资源状态与关联插件状态分离、项目登记与扫描、来源归属，以及原有变更恢复流程。

## 本轮范围

后续客户端兼容与原生验收另见《客户端兼容与原生验收》和 `docs/compatibility.json`。该阶段增加实例身份与版本证据、四层能力报告，以及 Windows/Codex CLI 0.159.2 用户级独立 STDIO MCP 的隔离原生配置验收。其他版本、HTTP transport、插件和项目 MCP 不复用该原生结果；既有手动实验性授权与报告证据分别判断。

本轮实现了可以启动和操作的本地管理器，覆盖基础工程、有限的只读资源扫描，以及 Codex 独立 MCP 的配置变更。完整产品设计仍见《实施方案》，本轮不代表开发任务清单中的全部功能已经完成。

| 模块 | 当前交付 |
| --- | --- |
| 前端 | Vue 3、TypeScript、Element Plus、Pinia；资源列表、详情、筛选、插件父子条目、实例登记、项目登记、操作记录 |
| 本地服务 | Fastify；仅监听 loopback；启动票据、会话 Cookie、CSRF、Host/Origin 检查、SSE |
| 数据库 | 实际使用 better-sqlite3；保存登记、资源绑定、计划、操作与事件 |
| 适配器 | Codex、Claude Code、官方 ZCode、DeepSeek Harness；扫描配置和本地目录，不执行客户端或扩展 |
| 配置变更 | Codex 独立 MCP：预览、应用、备份、恢复、摘要冲突检测、路径身份检查、目标锁、日志审计 |
| 开发体验 | pnpm workspace、开发启动、生产构建、最小 serve CLI、隔离演示、自动化测试 |

Skill 按作用范围、兼容分类和来源三维筛选。当前扫描器没有足够证据判断所有 Skill 的跨 Agent 兼容性，因此大多保持“尚未判断”；逐 Agent 兼容性筛选暂不可用。字段和筛选选项已经预留，不填造假的兼容结论。

资源目前以 `Binding` 为目录展示单位，通过 `resourceId` 关联来源。原生插件缓存已有只读版本索引；独立资源仓库、缓存安装/清理、分发和共享源修改尚未实现。

## 运行

在项目根目录执行：

```powershell
pnpm install
pnpm dev
```

打开服务输出的 **Vite 启动链接**，其中包含一次性票据；前端为 `127.0.0.1:5173`，API 为 `127.0.0.1:4780`。在空目录页点击“载入隔离演示数据”，可以直接检查 MCP 计划、应用和恢复。

生产模式：

```powershell
pnpm build
pnpm start
```

生产模式由同一个本地服务提供网页和 API。打开输出的启动链接。环境变量、数据目录和测试浏览器配置详见项目 README。

## 当前边界

- 已核对本机四种配置来源和 Codex 缓存布局，并记录 Codex/Claude CLI 版本；四个适配器尚未完成原生运行时及写入版本矩阵验证。具体证据与限制见《只读扫描兼容验证》和《适配器兼容边界》。
- 自动发现默认只读。真实配置写入要求手动登记并主动允许实验性修改；首轮仅支持可唯一定位的 Codex 独立 MCP 表。
- Skill、插件和其他客户端 MCP 的启用/停用仍为后续工作。插件附带的 MCP 不能通过独立 MCP 写入接口修改。
- “已启用/已停用”表示配置状态；“等待生效/运行状态未知”与真实运行状态分别展示。本轮不启动 Agent 或 MCP，不探测其实际运行情况。
- 原始计划和快照可能含凭据，保存在本地数据目录。Windows 使用继承的 ACL，尚未提供加密或显式限定当前用户的 ACL；浏览器 API 不返回配置原文。
- 尚未提供安装、更新、卸载、账号管理、任务调度、多 Agent 编排、自动升级迁移和完整桌面壳。
- Vue 构建目前仍有大 chunk 提示；后续可以按页面和组件拆分，不影响本轮本机功能验证。
