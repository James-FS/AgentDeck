# 资源库筛选精简实施方案

制定日期：2026-10-24。

状态：待实施。本轮只制定方案，不代表产品代码已修改或检查已通过。

## 1. 目标与最新规则

针对当前资源库筛选过多的问题，将常驻筛选下拉框从 8 个减为 4 个，取消独立的收藏/保存筛选整行、显示策略整行和常驻技术说明。

本轮要减少日常筛选维度，不是把原有 8 个控件全部转移到“高级筛选”。不新增高级筛选面板、条件构造器、诊断模式或复杂自动联动。

本文是最新的资源库筛选规范，覆盖以下旧要求：

- interaction-simplification-plan.md 中保留资源归类、配置或文件来源等诊断筛选，以及保留来源归属筛选的要求。
- 更早方案中要求全部既有筛选继续平铺的要求：本轮只要求保留的 4 个筛选直接平铺。
- 旧命名筛选必须继续执行所有旧条件的要求：本轮以可解释的兼容转换和提示替代，不能留下不可见的旧筛选。

客户端和项目选择继续集中在资源库，不恢复顶栏筛选。资源聚合、内置及仅缓存默认隐藏、独立可用性表单、固定扫描范围、权限与安全规则继续有效。

## 3. 最终界面

常态下工具区控制在两行；窄窗口自然换行，不通过缩小字号、裁切控件或新增横向滚动强行维持两行。

```text
全部  Skill  插件  MCP       搜索…  只看收藏  已保存视图

关联客户端   项目范围   资源来源   配置状态   显示选项
[有条件时] 客户端：Codex ×  项目：AgentDeck ×  包含全局  清除筛选

资源列表
```

类型页签、搜索、收藏、保存视图和显示偏好不算新增筛选下拉框。需要指定项目时，“包含全局资源”作为项目范围旁的条件复选框出现，不再另设一套范围下拉框。

### 3.1 保留 4 个筛选

| 筛选 | 内容与行为 |
| --- | --- |
| 关联客户端 | 全部或具体已登记实例；沿用现有实例选择，不再增加“所属 Agent”并行选择 |
| 项目范围 | 全部范围、仅全局、具体项目；选择项目时默认包含全局，可取消 |
| 资源来源 | 沿用独立来源、用户添加/导入、项目提供、插件附带、内置、组织、账号同步和未知等现有来源选项；不把文件存储位置塞入此菜单 |
| 配置状态 | 启用、禁用、未确认；沿用现有记录级匹配与状态证据 |

项目范围沿用上一轮已实现的全局/项目边界，不借本轮重新改写范围定义。未知范围与独立来源保持当前可解释的规则，不能为了合并控件自动视为全局、项目资源或已安装资源。

### 3.2 取消 4 个独立筛选

| 取消的控件 | 用户界面处理 | 数据处理 |
| --- | --- | --- |
| 配置/使用范围 | 常规全局/项目选择统一由项目范围承担；项目子目录等精确信息在可用性检查和详情中查看 | 不删除原始 scope 和范围证据 |
| 所属 Agent | 日常筛选统一使用关联客户端；公共、共享、未知作为详情信息 | 不把资源归属改写成关联实例，不声称二者等价 |
| 全部来源类型，即配置或文件来源 | 缓存、配置记录、本地文件在详情中解释 | 保留 origin 及证据，不与 sourceKind 混为一个字段 |
| 资源归类 | 用户全局、Agent 全局、项目公共等类别放入详情 | 保留 classification，不改变扫描结果和资源身份 |

这四项从常规筛选运行路径退出，不仅仅隐藏 HTML。检查 matchesRecord、独立发现匹配、隐藏搜索命中、计数及清除逻辑，避免旧状态在后台继续排除结果。

若为兼容旧类型暂时保留 scopeFilter、ownerAgentFilter、categoryFilter、originFilter 字段，它们必须保持中性且不参与运行时过滤。新界面不再生成这四类活动条件标签。不要为了兼容保留一个用户无法清除的隐藏条件。

## 4. 其他工具区压缩

### 4.1 收藏与已保存视图

“只看收藏”紧邻搜索，保留独立星标和现有收藏语义。

把保存当前筛选、应用已保存筛选和删除保存筛选合为一个紧凑“已保存视图”菜单：

- 菜单顶部：保存当前视图。
- 列表：已保存名称，点击应用，当前视图可标记。
- 提供删除入口，仅删除保存的条件，不删除资源。

没有已保存视图时显示空状态和保存动作。沿用现有命名输入方式即可，不新建复杂的视图管理页。选中视图后手动调整条件，不自动覆盖原视图。

菜单不能像当前下拉框一样铺满整行；有可访问名称，保存、应用、删除可用键盘完成。

### 4.2 显示选项

取消独立的显示策略整行，新增一个紧凑“显示选项”菜单，仅包含：

- 显示 Agent 内置资源。
- 显示仅缓存资源。

默认双关、持久化、清除筛选不改变偏好等现有行为保持。复选框点击后同步更新控件和列表，沿用偏好写入排队及旧响应保护。

菜单关闭时，按钮旁用短标记表达当前已开启的额外内容，例如“显示选项 · 内置”或“显示选项 · 内置、缓存”，避免隐藏生效状态。两个开关都关闭时无需写“显示策略默认……”的整段说明。

隐藏数量可放入菜单内简短显示，原因重叠时不直接相加。收藏被隐藏、搜索命中隐藏资源等实际情形保留有针对性的提示与现有显式显示动作。不得因移动控件而绕过隐藏策略。

显式选择内置来源时继续复用现有的开启内置显示行为，菜单复选框与按钮标记必须同步，不新增第二份开关状态。

### 4.3 帮助与异常

移除资源表上方常驻的唯一实体、版本记录、发现入口和加载边界长说明。在标题附近保留一个“资源说明”帮助入口，简短说明聚合和加载未验证，细节进入资源详情。

搜索执行中保留必要进度、失败、预算与“继续搜索”动作，不用每次展示完整搜索原理。结果未查完时继续明确提示，不能为了简洁声称无结果。

错误、同名冲突、扫描不完整、文件缺失、范围排除等实际问题仍须可发现；把解释搬进帮助不等于隐藏异常。

## 5. 清除与旧命名筛选兼容

只保留一个“清除筛选”：恢复全部客户端、全部范围、全部类型；清除搜索、来源、状态和收藏限定；保持内置与缓存显示偏好。此操作不影响独立的可用性检查表单。

新保存的视图只执行保留的条件及显示偏好。若共享契约仍要求四个旧字段，新写入使用中性值：scope=[]、owner=[]、category=[]、origin='all'。不为本轮引入新的存储版本系统或破坏旧偏好读取。

应用旧视图时：

1. 保留可直接支持的客户端、项目、类型、搜索、来源、配置状态、收藏和显示偏好。
2. 旧范围条件只有在与当前项目范围完全等价且不冲突时才转换；例如旧视图只有用户全局范围且没有具体项目，可映射为仅全局。不能把“仅项目级/项目子目录”随意映射为所有范围。
3. 所属 Agent、资源归类、origin 等不能等价表达的旧条件不再执行，不凭名称猜测关联实例，也不把配置记录/缓存猜测成资源来源。
4. 发生条件省略或无法转换时，一次性提示：“此视图含已取消的筛选条件，已应用其余条件，可重新保存。”提示可列出简短条件名，不能静默扩大结果范围。
5. 读取和应用时不自动覆盖或删除旧保存记录；只有用户显式保存时写入新版条件，删除仍需用户操作。

兼容转换提取成小型纯函数即可，避免在页面、store 和服务端重复编写不一致规则。若修改契约，完整同步校验与调用方，继续保留偏好并发保护。

## 6. 实施步骤

### A：去除冗余运行时筛选

核对现有八类条件，保留四个常驻控件，移除四个技术筛选及其运行时影响。保持身份聚合、来源证据和详情数据不变。适配旧视图、活动标签、清除、搜索与独立来源匹配。

### B：压缩工具栏

调整类型页签、搜索和收藏布局；合并已保存视图菜单；将显示偏好移入两项菜单；移除常驻技术说明。窄窗口换行，不影响核心操作。

### C：验收与文档

完成针对性测试和最终回归，检查两种窗口尺寸与键盘操作；更新 README；新增 docs/resource-filter-reduction-acceptance.md，记录实际行为、测试结果、截图和限制。

普通实现选择自行完成，不逐项等待用户批准。保留已完成交互成果，不借本轮重做扫描、资源实体、侧栏、路由或配置写入链路。

| 场景 | 必须结果 |
| --- | --- |
| 默认资源库 | 只有关联客户端、项目范围、资源来源、配置状态四个常驻筛选下拉框 |

| 原始来源和分类信息 | 详情仍可查看，扫描索引、身份、作用范围和权限不被改写 |
| 四个旧条件曾经非空 | 新列表不再被它们暗中过滤，搜索、计数、分页一致 |
| 应用含技术条件的旧视图 | 兼容读取，可转换条件准确转换，不支持条件明确提示省略，原记录不自动覆盖 |
| 保存、应用、删除视图 | 一个紧凑菜单即可完成，保留持久化和并发保护，不占独立整行 |
| 内置和缓存显示 | 默认隐藏不变，菜单中的两项偏好刷新后保留，已开启状态在菜单外可见 |
| 内置来源筛选、隐藏搜索或收藏提示 | 显示动作同步开关，不产生界面和实际过滤不一致 |
| 清除筛选 | 所有普通条件清除，显示偏好与可用性表单不变，无隐藏旧条件 |
| 搜索继续查询、截断和失败 | 保留准确状态与必要动作，不以压缩说明为由隐藏问题 |
| 资源详情、单项启停、多配置、收藏、对比 | 上一轮能力及真实引用不回退 |

| 键盘和可访问性 | 四个筛选、视图菜单、显示复选框、帮助和关闭菜单均有明确名称与焦点行为 |
