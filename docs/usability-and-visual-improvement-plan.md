# AgentDeck 易用性与视觉优化实施方案

制定日期：2026-10-23。

后续交互调整：关于顶栏统一客户端/项目上下文及可用性复用该上下文的旧要求，已由 [页面筛选与操作简化实施方案](interaction-simplification-plan.md) 替代。执行新一轮优化时以该方案为准，其余未被替代的能力与安全约束继续保留。

本方案 A、B、C 已于 2026-10-23 增量实施，结果与限制见 [本轮验收记录](usability-and-visual-acceptance.md)。以下保留原实施要求。新对话应先核对当前源码，再按本文实施；不得将历史验收结果当作本轮验证结果。

## 1. 目标与现状

AgentDeck 已具备客户端资源盘点、独立 Skill 来源、详情与内容搜索、项目可用性检查、增量扫描与监听、收藏与命名筛选、目录打开、Skill 对比和变化记录。本轮重点是让这些已有能力更容易找到、理解和使用。

当前需要解决的问题：

1. 资源页把来源登记、项目可用性、扫描报告、变化记录、独立来源、搜索结果和资源表依次堆叠，主列表位置靠后。
2. 资源名称旁并列多个操作，文字和标签拥挤；详情分别使用绑定抽屉和 Skill 弹窗，阅读入口不一致。
3. 顶栏和项目可用性区域分别选择客户端、项目，范围容易产生歧义。
4. 名称/路径筛选与正文搜索呈现为两套结果；正文搜索本身有候选分页和读取预算，不能将一页无命中解释为没有结果。
5. 扫描诊断较详细，但用户需要自己判断如何处理；磁盘发现、配置状态、文件检查和实际加载的区别需要更简洁地表达。
6. 表格最小宽度、固定侧栏和内边距在笔记本窗口下容易产生横向滚动；部分有意义的小字颜色偏浅。
7. 连续事件可能触发重复整页刷新；双击启动每次同步依赖并构建，存在优化空间。

## 2. 范围与原则

- 沿用 Vue、Pinia、Element Plus、Fastify 和现有 TypeScript monorepo，不更换技术栈，不做无关重构。
- 保留绿色品牌色和浅色界面，优先调整信息层级、排版、交互和状态表达。
- 收藏、保存筛选、对比、监听和目录打开已经实现，复用现有契约与安全校验。
- 磁盘发现、配置引用/启停、文件格式有效、客户端实际加载分别表达；没有实际证据时仍显示加载情况未确认。
- 不自动安装、移动、同步或执行资源，不扩大写入权限，不启动真实 Skill、插件或 MCP 进程。
- 独立发现与客户端绑定可以在统一资源库中浏览，但必须保留身份和来源区别。同物理资源的多个绑定不能合并成一个配置开关。
- 现有目录边界、物理路径证据、链接策略、读取限额、监听关闭排空和偏好写入竞态保护继续有效。
- 当前工作区包含前几个阶段及 README 的未提交修改。先记录现状，在此基础上增量修改，不重置、覆盖或擅自提交。
- 暗色主题、移动端完整重做、云同步、自动安装市场和新的客户端适配器不属于本轮范围。

## 3. 实施方式

由当前对话的智能体直接完成分析、实现、调试、自检和验收，无需指定模型或委派子智能体。此前阶段文档中的角色分工仅为历史记录，不作为本轮实施要求。

1. 先阅读 README、本文、当前适用的 AGENTS.md（如存在）、第三阶段方案与验收记录，再检查相关源码和测试。
2. 根据实际代码确认文件范围、数据流和验收标准；必要调整记录在本方案中。
3. 按 A → B → C 逐批实施，独立调试和自检，每批保持可运行状态。
4. 检查关键差异、安全与状态边界，复验关键流程，发现问题后直接修复并完成验收。
5. 仅在架构冲突、重大风险或无法解决的阻塞时请求用户决策；完成后报告修改文件、验证命令与实际结果、截图和遗留项。

## 4. 实施批次 A：资源页与视觉整理

### A1. 资源优先的信息结构

资源管理页面提供以下页签，默认打开“资源库”：

| 页签 | 内容 |
| --- | --- |
| 资源库 | 搜索、常用筛选、收藏/命名视图、绑定与独立资源列表、对比选择 |
| 来源与扫描 | 来源登记、扫描模式、监听、完整度、错误候选、跳过/截断报告与重扫 |
| 项目可用性 | 当前客户端、项目和工作目录的文件检查、配置状态、冲突与范围解释 |
| 变化记录 | 独立来源和客户端的现有变化记录，保留各自范围和时间语义 |

资源库首屏直接出现资源行。已有来源和诊断都应能从对应页签找到，不能通过隐藏组件悄悄删除能力。空状态提供发现客户端、添加 Skill 来源、载入隔离演示数据三个明确入口，扫描高级选项折叠。

默认将登记的独立来源结果与绑定资源放入同一浏览入口，显式标注“独立来源”或客户端/项目绑定；保持稳定资源引用、分组和收藏语义。若现有行模型不足，先扩展展示模型，不把独立来源伪造成可写绑定。

### A2. 上下文与筛选

- 顶栏作为客户端和项目选择的唯一状态来源，项目可用性复用该上下文，仅保留自己的工作目录输入。
- “全部客户端/全部项目”表示浏览范围，不可用作一个具体客户端的可用性判定。需选择客户端时显示清楚的引导。
- 选择具体项目时定义一致的用户级资源继承/显示规则，清楚解释当前范围；切换上下文不得残留不匹配的工作目录和旧可用性结果。
- 常用筛选显示类型、状态、来源；其他条件收进“更多筛选”。活动条件以可移除标签显示，支持清空。（2026-10-24 调整：按用户要求取消“更多筛选”开关，全部筛选条件在工具栏直接平铺，空间不足时换行。）
- 收藏和命名视图保留持久化行为，命名视图恢复上下文时处理失效引用，不悄悄改指其他资源。
- 使用“刷新页面数据”“重新扫描文件”等明确文案区分读取已有目录与触发新扫描。

### A3. 行操作、详情与对比

- 行首保留收藏，名称打开详情，其他次要操作收进末尾菜单；配置开关和预览入口保持明确可见的权限说明。
- 建立统一详情容器，绑定与独立来源共用摘要、路径、元数据和正文阅读；绑定独有的配置/证据区按需展示。插件和 MCP 详情继续可用。
- 外部图片、HTML、链接和 Markdown 长度限制沿用现有安全实现；路径复制保留浏览器不支持时的回退。
- 对比选择条显示数量、已选名称、移除和清空，提供进入对比的入口；选中项跨筛选或页签仍可解释，资源失效时明确提示。
- 对比增加有界的行差异高亮、上一处/下一处差异和截断说明；长内容避免无界计算。复用现有每侧正文限制，不把截断部分或整个 Skill 包宣称为一致。

### A4. 排版与响应式

- 保留品牌色 `#1F7A57`，主要操作使用绿色，普通行操作使用中性色；状态同时使用文字表达。
- 正文和主要控件约 14px，辅助信息约 12px；建议行高 56–64px、常用按钮高 32–36px，按实际密度调整。
- 有意义的小字达到普通文本 4.5:1 的对比度目标。当前 `#8A968F` 在白底约 3.07:1，需加深或替换；禁用状态和纯装饰另行判断。
- 搜索/筛选和表头按容器保持可见，尽量采用一处主要纵向滚动，避免互相争抢的嵌套滚动。
- 窄窗口折叠侧栏、压缩或隐藏次要列、展开查看长路径。核心名称、状态和主要操作不依赖横向滚动；对比正文等宽内容允许在明确区域内滚动。
- 图标操作有可访问名称，菜单、页签、详情和对比可用键盘完成，关闭详情后焦点回到触发处。
- 保留适量间距和细边框，减少重复说明和同时堆叠的成功通知；重要错误和部分扫描提示不能被吞掉。

布局参考：

```text

当前范围：全部客户端 / 全部项目

资源库 | 来源与扫描 | 项目可用性 | 变化记录

搜索名称、描述、内容……
类型  状态  来源  更多筛选       收藏 / 已保存视图
活动筛选：……

收藏  名称与简短描述  来源/范围  状态  操作
 ☆    example-skill   独立来源   已发现  ⋯
```

## 5. 实施批次 B：搜索与识别结果说明

### B1. 统一搜索体验

- 一个搜索入口展示名称/路径及元数据/正文命中，提供匹配片段和命中类型，避免重复呈现同一资源。
- 保留候选分页、读取预算、失败数、截断提示和继续查询能力。页面无命中而仍有后续候选时显示“当前范围尚未查完”。
- 不为了合并界面一次性读完所有 manifest。异步搜索防抖，并用请求序号或取消机制阻止旧结果覆盖新输入/上下文。
- 明确内容搜索与类型、来源、上下文和收藏筛选如何组合；匹配片段使用安全文本，不执行内容。

### B2. 识别说明与问题入口

- 复用现有扫描报告，按“目录未覆盖、被跳过、格式异常、链接边界、来源失效、范围不匹配”等实际原因提供可理解说明。
- 展示来源路径、扫描时间、扫描完整度和对应处理动作。例如快速扫描未覆盖嵌套目录时引导深扫或登记更具体的入口。
- 修复动作限于现有显式登记、重扫、检查等能力，不自动越界跟随链接、取消限额或修复磁盘文件。
- 统计使用“资源记录”等准确名称，分别解释绑定与独立记录；若展示去重数量，必须给出明确身份依据和计数口径。
- 状态采用短标签，详细边界放入提示或详情；扫描时间、配置状态时间和当前文件检查时间不能混用。

## 6. 实施批次 C：刷新、性能与启动

### C1. 刷新与渲染

- 合并短时间内的重复目录事件，避免同一次操作的 `catalog.changed` 和 `operation.completed` 引起重复全量刷新。
- 对并发刷新使用明确的请求时序和待刷新标记：旧响应不覆盖新状态，刷新期间到来的新事件最终仍被读取。
- 目录更新时不重复获取没有变化的适配器能力、兼容性和用户偏好；显式操作后仍能更新相应数据，保留原有偏好写入保护。
- 根据构建产物拆分非首屏页面或详情依赖，核对拆分后的加载行为与实际产物，而不是单纯调高告警阈值。
- 用隔离生成的数据测量 100、1,000 条资源记录下的筛选、滚动和刷新。仅在测量表明需要时使用分页或虚拟列表，不以演示几条数据推断性能。
- 记录浏览器、数据规模、测量方式和结果；不在未测量前承诺固定耗时指标。

### C2. Windows 启动快路径

- 无变化且已有有效产物时直接启动；保留明确的“更新并重建”入口或脚本参数。
- 用可靠指纹判断依赖及构建是否有效，至少覆盖锁文件、各 workspace 清单、源码与构建配置、预期产物是否存在。依赖状态与构建状态分别判断。
- 首次运行、依赖缺失、源码/配置变化、产物缺失或状态不可验证时走安装/构建路径。指纹仅在对应步骤成功后更新，失败不能标记为完成。
- 不只比较单个文件时间戳，不启动已知过期构建；删除源码、修改 workspace 清单也必须触发重新判断。
- 保留用户显式设置的端口、默认自动端口、一次性票据、自动开浏览器、Ctrl+C 和失败时保留窗口等行为。
- 保持 CMD 入口的 ASCII/CRLF 兼容和 PowerShell 的正确中文编码；以隔离脚本测试验证安装/构建分支，避免测试反复变更真实环境。

## 8. 验收标准

### 功能与交互

- [ ] 资源库默认展示，已有数据时首屏能看见资源行；来源、诊断、可用性和变化功能均可找到。
- [ ] 绑定与独立来源可以统一浏览，引用、收藏、来源及权限语义正确；分组不合并配置开关。
- [ ] 客户端/项目上下文唯一，切换后筛选、搜索与可用性结果一致，没有旧异步响应回写。
- [ ] 行操作精简，鼠标与键盘均可完成详情、收藏、复制、打开目录、对比；插件/MCP 详情和原有配置流程可用。
- [ ] 命名视图、收藏和监听偏好重启后保留，失效引用给出明确提示。
- [ ] 统一搜索保留分页、预算和失败语义；一页无命中时仍可继续，结果不会被旧请求覆盖。
- [ ] 对比显示已选资源、差异位置与截断状态，计算有界，不扩大“一致”的结论范围。
- [ ] 诊断原因有依据、处理入口可用；发现/配置/文件检查/实际加载状态没有混淆。

### 视觉与适配

- [ ] 1280×800、1440×900 下，分别以浏览器 100% 和 125% 缩放检查；核心列表和操作不依赖横向滚动，弹窗不超出可用区域。
- [ ] 长名称、长路径、多来源、错误、空数据、加载中和大量记录均有可读布局。
- [ ] 关键正文和辅助信息对比度达到普通文本目标；焦点可见、图标有名称，状态不只靠颜色区分。
- [ ] 搜索/表头保持可定位，滚动无明显冲突；保存上述尺寸及关键详情、对比的截图。

### 性能与启动

- [ ] 连续重复事件被合并，刷新途中发生的新变化不丢失，旧响应不覆盖偏好或目录。
- [ ] 提供 100/1,000 条隔离数据测量及构建产物对比，说明采取或暂不采取虚拟列表的依据。
- [ ] 正常无变化启动跳过无必要步骤；首次、缺依赖、改清单/锁文件/源码/配置、删产物及强制重建分支均正确。
- [ ] 构建失败不更新成功标记，不启动旧产物；动态端口和浏览器连接行为保持有效。

### 回归与安全

- [ ] 保留第三阶段路径边界、监听关闭、局部扫描变化基线、偏好竞态和安全 Markdown 的既有保障。
- [ ] 所有测试使用隔离夹具与临时数据；目录打开使用注入替身，不启动真实资源进程，不读写真实用户配置。
- [ ] README 与实际交互和启动行为一致；验收记录列出真实命令、结果、跳过项和限制。

## 9. 验证与交付

按改动选择有意义的测试，不为纯样式或简单组件拆分新增镜像测试。为上下文切换、搜索/刷新竞态、分页语义、长文本对比及启动指纹失效增加针对性检查。

本轮最终验证命令：

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:e2e
```

浏览器测试使用最新构建，默认隔离运行；真实客户端 opt-in 验收保持关闭。构建告警、环境导致的跳过和无法执行的检查均应如实记录，不以历史通过结果代替。

在 `docs/usability-and-visual-acceptance.md` 交付本轮验收记录，包含各批次完成项、关键文件、实际验证结果、截图位置、性能测量及已知限制。对明确因测量结果而不采用的可选技术给出理由，不标成未完成必需功能。
