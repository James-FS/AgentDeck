# 插件缓存版本分组

更新：2026-10-04。资源表格将同一实例、同一项目、同一完整插件身份（含市场）的配置记录和已核实缓存版本折叠成一组，默认折叠。适用于四适配器已提供完整身份的记录，不按显示名称合并资源。

分组显示“版本分组”、缓存版本数、配置记录数和“当前使用版本未确定”。点击分组标题或展开按钮后，显示各版本原始记录与匹配的 Skill/MCP 子组件；配置记录、缓存版本与版本号分别标记。点击原始记录仍打开真实来源路径和详情。筛选/搜索只显示命中的版本及相关父项；组内总版本数仍描述已索引库存。

例如本机 ZCode 的 computer-use 保留 0.5.13、0.5.14、0.6.1、0.6.3 四个缓存版本及其配置记录。多个同名 Skill 分别属于这些版本；不是四个版本同时加载。没有选择最大版本、没有把配置允许当作缓存版本正在使用。

边界：

- 不跨 Agent 实例、项目或市场分组；身份冲突/未经核实的 manifest 与仅凭名称发现的插件保留独立条目。
- 只改变前端展示树，不合并或删除后端 Binding、原始文件、来源或稳定 ID；统计数字继续按原始记录计数，页脚改为显示行数。
- 分组配置状态优先汇总组内明确配置记录；无配置时汇总缓存关联状态。冲突或证据不足时未确定。它不代表某个缓存版本使用状态。
- 分组已有操作使用真实且已获授权的资源目标，仍是插件身份整体开关，既有启停、预览、备份与恢复校验保留；未扩大写入权限。
- 没有完整插件身份、只有单个版本记录的插件，仍使用既有组件展开方式，版本号仍明确标记。

新增五项展示树测试，覆盖原始记录完整保留、操作目标不伪造、实例/项目/市场隔离、身份冲突、子项搜索和配置冲突。隔离浏览器用四版本 computer-use 验证默认一行、展开/收起、Skill 过滤、版本标签和真实来源详情；已有控制与恢复继续回归。
