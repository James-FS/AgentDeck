# AgentDeck 初期基础版使用与验收

日期：2026-10-02（Asia/Hong_Kong）。对应实施方案 1.2 的初期范围。基础版成果随本次 Git 提交归档；完整 T01–T42 路线仍延期。

## 启动与查看

使用 Node.js 24.7.0、pnpm 11.22.0，在仓库目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

打开终端打印的一次性启动链接。生产服务直接提供网页和 API，不需要 Vite。首次点击“扫描本机配置（只读）”或“发现并扫描本机资源”，然后按实例、项目、类型和来源筛选；“重新扫描已登记实例”用于手动刷新。项目页登记明确项目根后可以扫描该项目。配置状态、缓存是否存在和运行状态分别展示，缺失与未知不会推断成已运行。

调试可使用 `pnpm dev`，默认数据和扫描目录在 `work/` 内。通过“载入隔离演示数据”可以体验 MCP 预览、应用和恢复。

分组 Skill 在列表中带“仅磁盘发现”标记和相对分组路径；同名条目可据此区分。详情还会显示发现级别与分组路径。

| Codex 本地市场插件 | 已检查为 CLI 0.159.2 / Windows 后，已有缓存与配置身份精确关联、`marketplaces.<市场>.source_type = "local"` 的插件可修改整体 `enabled` | 远程/未知市场、未配置缓存、身份冲突、配置状态未知、项目插件只读；子组件不提供独立开关 |

Skill 原文和插件缓存不会被本应用的启停操作改写。Skill 开关只针对该 Codex 实例的按路径覆盖；插件开关针对完整 `name@marketplace` 身份，影响其全部缓存版本以及 Skill/MCP/其他组件，不表示切换了某个缓存版本。

自动发现始终只读。有控制需求时，在实例页重新登记相同配置根并勾选“允许 Codex 配置修改（仅支持的单项资源）”；应用会合并登记记录并刷新资源。Skill/插件还需点击该实例的版本检查；检查只执行隔离 `--version`，之后刷新控制权限。未匹配版本继续只读。版本证据失效或权限撤销会阻止新控制计划应用。

## 预览、应用与恢复

1. 在资源行点击“计划停用”或“计划启用”。检查抽屉中的目标、关联资源、脱敏差异及摘要；此时配置尚未写入。
2. 点击“确认应用计划”。服务重新检查权限/已验收范围（新 Skill/插件控制）、文件摘要、路径身份与结构，先备份再修改。配置变化时拒绝覆盖，重新扫描并规划。
3. 应用成功显示配置已启用/停用；当前会话加载或 MCP 连接状态显示“暂未检测”。根据官方 Skill 文档，变更后重启 Codex；AgentDeck 不确认生效时间。
4. 在“操作记录”中对有备份的成功操作创建恢复计划，预览后应用。恢复整个配置文件到该操作前的原始字节，包括 BOM、换行、注释和未知字段。目标已被外部修改或文件身份变化时拒绝恢复。
5. 已经处于目标状态的无改动操作不会创建恢复快照，历史页显示“未改动，无需恢复”。不要通过连续恢复更早记录来覆盖之后的编辑；优先处理最近操作。

管理器数据保存在 `AGENTDECK_HOME` 指定目录。原始计划和快照仍以明文保存，Windows 使用继承 ACL；部署时使用当前用户私有目录。普通 API 和计划差异不返回原配置中的凭据。高级权限/保留策略与独立安装包专项属于后续范围。

## 原生依据与验收方法

[OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)说明按 `SKILL.md` 路径的 `[[skills.config]]` 开关及重启要求。[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)提供 `skills/config/write`、`skills/list` 和配置复读接口。[插件文档](https://developers.openai.com/plugins/build/plugins)说明本地市场格式和市场登记。文档依据与实际验收分开记录。

本机 Codex CLI 0.159.2 / Windows 的隔离验收：创建纯合成 Skill 和无可执行组件的本地插件；以 CLI 登记隔离本地市场/插件，并以 `skills/config/write` 生成原生配置。应用随后只通过 AgentDeck 计划引擎修改用户配置，用新的隔离 app-server `skills/list` 和 CLI `plugin list --marketplace local --json` 复读停用、启用和恢复状态。没有启动模型线程、MCP 握手、hook 或 Skill 执行，也未接触真实账号。

原生测试启停和恢复分别保留 BOM/CRLF/注释/无关字段，验证 Skill 原文与插件缓存摘要不变；78 个真实来源文件摘要不变。自动服务测试另外覆盖鉴权、CSRF、未知版本、授权撤销、可执行文件替换、外部编辑冲突、重复/inline 覆盖、序列化恢复和数据库提交中断。配置加载证据不等于运行时观察。

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:e2e
```

普通测试默认跳过真实原生验收与真实来源浏览器扫描。显式复验：

```powershell
$env:AGENTDECK_VERIFY_NATIVE_CODEX='1'

pnpm test:e2e
Remove-Item Env:\AGENTDECK_VERIFY_REAL_CLIENTS
```

测试配置、数据库、工作目录及环境都隔离。原生新控制要求精确版本 0.159.2，不把其他版本运行结果外推。证据：`tests/codex-controls.test.ts`、`tests/native-codex-controls.test.ts`、`tests/browser/codex-controls.spec.ts`；本机摘要与截图保留在忽略目录 `work/compatibility-proof/native-codex-controls.json` 和 `work/browser-proof/basic-*.png`。
