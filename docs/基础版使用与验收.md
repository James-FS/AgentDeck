## 启动与查看

使用 Node.js 24.7.0、pnpm 11.22.0，在仓库目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

打开终端打印的一次性启动链接。生产服务直接提供网页和 API，不需要 Vite。首次点击“扫描本机配置（只读）”或“发现并扫描本机资源”，然后按实例、项目、类型和来源筛选；“重新扫描已登记实例”用于手动刷新。项目页登记明确项目根后可以扫描该项目。列表将资源归类、范围、所属 Agent 分为三列，另显示来源、配置状态和启停；详情补充缓存与证据。配置状态只表示静态设置，不证明资源已加载。

调试可使用 `pnpm dev`，默认数据和扫描目录在 `work/` 内。通过“载入隔离演示数据”可以体验 MCP 预览、应用和恢复。

客户端适用性及运行状态的列、筛选和详情已移除，运行状态 API 已删除；当前不提供会话加载/连接检测。客户端版本和配置支持证据保留，供控制校验使用。列表原控制能力列已改为启停，详情保留控制边界。

2026-10-03 增加 Skill 静态盘点：已登记 Skill 根目录内最多扫描 3 层目录，列表优先显示 `SKILL.md` frontmatter 的名称和描述，详情保留实际来源路径与目录名身份。分组目录条目仅证明磁盘上发现文件，配置状态未知、保持只读；不代表客户端版本可见，更不代表当前会话已加载。frontmatter 不参与开关定位，解析失败时显示目录名。
分组 Skill 在列表中带“仅磁盘发现”标记和相对分组路径；同名条目可据此区分。详情还会显示发现级别与分组路径。

## 资源分类与筛选

重新扫描后，Skill、MCP、插件均支持“作用范围”和“所属 Agent”组合筛选，另可筛选有证据的共享来源与未知归属。用户全局不限定项目，也不表示所有 Agent 共用；所属 Agent 表示配置或扫描来源，不证明内容专用。列表与详情显示项目名称、实际来源路径、配置证据文件及分类依据；未关联配置的缓存可显示有证据的 Agent 存放归属，但其配置/使用范围未知，并标明仅磁盘发现。旧索引没有证据时保持未知并提示重新扫描。

项目只扫描明确登记的根；列表项目选择可同时显示用户资源，仅看项目时再选择项目级范围。当前没有足以确认的项目子目录生效范围，不根据分组路径推断。共享来源仅说明同一实际资源已在多个 Agent 索引下出现，同名副本分别保留。不评估资源内容客户端适用性。详细覆盖、剩余缺口与测试见[资源分类展示与筛选](./资源分类展示与筛选.md)。

Skill 原文和插件缓存不会被本应用的启停操作改写。Codex Skill 开关针对该 Codex 实例的按路径覆盖，ZCode Skill 开关针对该 ZCode 实例的路径 enable 覆盖；插件开关针对完整 `name@marketplace` 身份，影响其全部缓存版本以及 Skill/MCP/其他组件，不表示切换了某个缓存版本。

受支持资源默认允许启停，重扫旧索引后直接切换，无“开放启停”按钮。实例登记页“允许资源启停（仅目标开关）”默认勾选；取消后显式只读选择会保留，登记不会改变客户端配置。Codex Skill/插件还需点击该实例的版本检查；检查只执行隔离 `--version`，之后刷新控制权限。未匹配版本继续只读。版本证据失效或权限撤销会阻止新控制计划应用。

## 预览、应用与恢复

1. 已开放的资源可直接切换启停，后台自动生成并应用受保护的计划。若需先查看差异，点击开关旁信息图标打开预览。检查抽屉中的目标、关联资源、脱敏差异及摘要；此时配置尚未写入。
2. 使用预览入口时点击“确认应用计划”；直接开关则自动应用。服务重新检查权限/已验收范围（新 Skill/插件控制）、文件摘要、路径身份与结构，先备份再修改。配置变化时拒绝覆盖，重新扫描并规划。
3. 应用成功显示配置已启用/停用；页面不展示会话加载或 MCP 连接状态。根据官方 Skill 文档，变更后重启 Codex；AgentDeck 不确认生效时间。
4. 在“操作记录”中对有备份的成功操作创建恢复计划，预览后应用。恢复整个配置文件到该操作前的原始字节，包括 BOM、换行、注释和未知字段。目标已被外部修改或文件身份变化时拒绝恢复。
5. 已经处于目标状态的无改动操作不会创建恢复快照，历史页显示“未改动，无需恢复”。不要通过连续恢复更早记录来覆盖之后的编辑；优先处理最近操作。

管理器数据保存在 `AGENTDECK_HOME` 指定目录。原始计划和快照仍以明文保存，Windows 使用继承 ACL；部署时使用当前用户私有目录。普通 API 和计划差异不返回原配置中的凭据。高级权限/保留策略与独立安装包专项属于后续范围。

## 历史原生依据与复验方法（不自动执行）

[OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)说明按 `SKILL.md` 路径的 `[[skills.config]]` 开关及重启要求。[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)提供 `skills/config/write`、`skills/list` 和配置复读接口。[插件文档](https://developers.openai.com/plugins/build/plugins)说明本地市场格式和市场登记。文档依据与实际验收分开记录。

本机 Codex CLI 0.159.2 / Windows 的隔离验收：创建纯合成 Skill 和无可执行组件的本地插件；以 CLI 登记隔离本地市场/插件，并以 `skills/config/write` 生成原生配置。应用随后只通过 AgentDeck 计划引擎修改用户配置，用新的隔离 app-server `skills/list` 和 CLI `plugin list --marketplace local --json` 复读停用、启用和恢复状态。没有启动模型线程、MCP 握手、hook 或 Skill 执行，也未接触真实账号。

原生测试启停和恢复分别保留 BOM/CRLF/注释/无关字段，验证 Skill 原文与插件缓存摘要不变；78 个真实来源文件摘要不变。自动服务测试另外覆盖鉴权、CSRF、未知版本、授权撤销、可执行文件替换、外部编辑冲突、重复/inline 覆盖、序列化恢复和数据库提交中断。配置加载证据不等于运行时观察。
