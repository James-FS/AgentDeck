# 页面筛选与操作简化验收记录

日期：2026-10-24。按 [页面筛选与操作简化实施方案](interaction-simplification-plan.md) 在含前序阶段未提交成果的工作区上增量完成 A → B → C → D；未提交、未推送 Git，未删除磁盘资源，未修改真实用户客户端配置。

## 完成范围

- **A（集中筛选、拆开页面状态）**：顶栏移除客户端/项目下拉框，只保留面包屑和一个“刷新当前页面数据”按钮。资源库筛选集中到资源页签：新增 **关联客户端**（`library-client-filter`，默认全部）与 **项目范围**（全部范围 / 仅全局 / 指定项目），指定项目时显示默认勾选的“包含全局资源”。项目范围语义按方案表格实现（`useResourceRows.ts`）：仅全局只认 `scope: 'user-global'`；`projectId` 为 null 或范围未知的记录不伪装成全局，只在“全部范围”可见；所有条件作用于同一条关联记录。独立来源仅在“全部客户端 + 全部范围”进入列表，被排除时显示原因和“查看独立来源”动作（`viewIndependentSources`：重置客户端与范围、选中独立来源，不建立绑定）。活动条件标签新增客户端、项目范围与“不含全局资源”芯片，可逐个移除；“清除全部”同时重置客户端与项目范围和普通条件，保留显示策略开关，不触碰可用性表单。项目可用性改为独立表单（实例必选、项目可选、工作目录默认项目根），只在点击“检查可用性”时请求；修改任一输入即取消在途请求并把旧结果标记为待重新检查（`availability-stale`），首次进入页签一次性带入已明确选择的资源库客户端/项目，之后不双向同步。总览统计卡与统计数字改用全局口径（`useResourceRows({ global: true })`），不再读取资源库残留条件。命名筛选契约新增 `projectScope` / `includeGlobal` 可选字段（Zod strict、服务端直存）；旧记录映射：已存 projectId → 指定项目且默认包含全局，无项目 → 全部范围（`savedFilterScope`，含损坏数据回退）。
- **B（固定扫描、统一刷新）**：`useScanActions` 拆为 `scanClients`（`{ scanRegisteredProjects: false }`）、`discoverClients`（`{ discover: true, discoverUserHome: true, scanRegisteredProjects: false }`）、`scanProject(projectId)`（只传 `{ projectId }`），不读取任何浏览筛选或可用性表单。资源页主操作“扫描客户端”+ 次要菜单“发现客户端”；总览不再铺设扫描按钮；实例页保留发现与登记；项目页保留登记（唯一入口）与行内扫描。扫描后不再 `clearFilters`、不自动切页、不清空上下文；项目扫描结果在项目行显示（`project-scan-notice`）并提供显式“查看资源”（设置指定项目 + 全部客户端 + 包含全局，清理普通条件，保留显示偏好）。刷新统一为顶栏一个入口；资源面板与操作记录页的正常状态刷新按钮删除，错误态“重试”保留。刷新不清空筛选/工作目录/收藏/命名筛选；SSE 合并、请求序号与旧响应保护沿用。
- **C（精简按钮、说明和记录）**：来源入口改名“添加 Skill 目录”，“添加并扫描”；来源行常驻“重新扫描”、自动更新开关（Element 开关，平台不支持时禁用，状态与错误原因始终可见）和“⋯”菜单（改用深度扫描、强制完整扫描、复制路径、取消登记——菜单注明不删除文件）；扫描不完整时的“继续扫描”保留为针对性行内按钮；深度、限额、缓存复用与诊断收进“扫描报告详情”展开区。行内与详情启停预览由信息图标改为“预览修改”文字按钮；“管理绑定”→“管理配置”、“查看绑定”→“查看关联配置”。资源页签“变化记录”→“扫描变化”，且不再在该页签重复渲染来源报告与管理按钮，只汇总来源变化并提供“查看来源”跳转；主导航与页面标题改为“配置操作记录”，“创建恢复计划”→“恢复此修改”（仍先进恢复预览确认）。项目页删除列表标题的重复“登记项目”按钮，项目行提供“扫描项目”与“查看资源”。
- **D（回归与文档）**：新增单元测试 `tests/library-scope.test.ts`（8 项）与浏览器用例 `tests/browser/interaction-simplification.spec.ts`；适配既有浏览器用例的文案与选择器；README 按最终实现更新。

## 已知限制

1. **“仅全局”只认 `scope: 'user-global'`**：用户级独立 MCP（`scope: 'native'`）不进入“仅全局”，只在“全部范围”可见。方案要求“可靠用户级全局范围证据”，原生特殊范围不视为可靠全局证据；如需放宽需先补充分类证据。
2. **指定项目不再包含 `projectId` 为 null 的未知范围记录**（旧交互把它们当作项目上下文的一部分）。这些记录在“全部范围”仍可见，符合方案“范围未知不能宣称为全局”的要求，但与旧版结果有差异。
3. **可用性表单不随目录数据自动刷新**：目录在别处更新后，表单内旧结果仅在再次点击“检查可用性”或修改输入时更新/标记过期；这是“点击才请求”约定的直接结果。
4. **“查看资源”导航会清理普通筛选**：按方案清理与该显式导航冲突的普通条件，仅保留显示策略；不保存当前命名筛选的未保存修改。
5. **真实客户端 opt-in 验收未启用**（`AGENTDECK_VERIFY_REAL_CLIENTS` / `AGENTDECK_VERIFY_NATIVE_CODEX` 保持关闭）；本轮未新增真实客户端路径，未执行真实 Skill、MCP 或版本命令。
6. **1920×1080 截图规格修正**：上一轮验收记录中 `library-1920x1080.png` 的“1920×1080”描述与实际输出（1440×1000）不符；本轮修正截图方式并核实尺寸，上一轮记录保持原文不改写。
7. 浏览器规模测量（`library-scale: refresh-to-50-rows`）为单次采样（本轮约 0.8–1.2 s，含请求与测试开销），仅证明分页实体模型无数量级回退。
