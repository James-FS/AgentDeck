# 资源启停说明

更新：2026-10-04。列表原“控制能力”列改为“启停”：有明确配置开关的资源可直接切换，未支持的资源继续显示只读。启停只保存目标布尔开关，不编辑模型、连接参数、资源正文或插件缓存，也不启动或执行资源。

## 使用方法

构建并重启后台、刷新网页，再重新扫描。受支持的 Codex、ZCode、Claude Code 和 DSH 资源默认允许启停，自动发现和手动登记均无需点击“开放启停”。旧索引重扫时迁移默认权限，仅修改 AgentDeck 索引，不修改客户端配置；Claude/DSH 旧版本默认策略因当时未支持而锁定的实例也会迁移，明确选择只读的实例不迁移。实例登记页“允许资源启停（仅目标开关）”默认勾选；如需只读可取消，之后的重扫与再次发现保留此选择。直接点击资源开关，成功保存才刷新显示状态；失败时显示原因并重扫。

开关旁的信息图标保留预览入口，直接切换也经过后端计划、摘要校验、备份与应用。操作记录中仍可预览并恢复最近的备份；外部编辑、文件身份变化或撤销许可时拒绝覆盖。配置开关变化不证明当前会话已加载；客户端何时读取新配置仍由客户端决定，必要时重启客户端。

## 当前支持

| Agent / 资源 | 修改位置与边界 |
| --- | --- |
| ZCode 用户级 Skill | 已存在的 `cli/config.json` 中 `skills[完整 SKILL.md 路径].enable`；缺省开关可新增。保留已有路径键拼写；重复或无效目标只读。公共 Skill 也只写此 ZCode 实例的覆盖。插件 Skill 仅在其父插件明确已启用并关联该配置时开放。 |
| ZCode 用户级插件 | `plugins.enabledPlugins[完整插件身份]`。只开放配置记录或能精确关联安装登记的缓存；只有缓存、没有配置或安装登记的 ios-simulator 一类条目仍只读。插件整体开关不选择缓存版本。 |
| ZCode 用户级独立 MCP | `mcp.servers[名称].enable`，已有 `enabled` 时保留该字段；其他命令、参数和环境设置不变。插件 MCP 与项目 MCP 不提供独立开关。 |
| Codex 用户级独立 MCP | 复用已有 `config.toml` 目标 `enabled` 控制与实验性传输策略；默认开放受支持目标，显式只读登记除外。 |
| Codex 独立 Skill / 本地市场插件 | 复用既有按路径覆盖或完整插件身份的 `enabled` 控制；仍限原有版本、来源和结构校验，不扩大已验收范围。 |
| Claude Code 用户级插件 | 已有 `settings.json` 中 `enabledPlugins[name@marketplace]`。开放明确配置记录、身份核实且精确关联 user 安装登记的缓存，或明确 user 登记且安装目录在配置根内存在的记录（原生 LSP 可没有独立 manifest），缺省开关可新增。不外推缓存可用性；插件版本共用身份开关，不改缓存/安装登记；只有缓存、范围未知的安装记录、项目记录、`@synced`、非法/重复键只读。 |
| DSH 用户 profile 插件行 | 已有配置根 `cordis.patch.yml/yaml` 或 `profiles/<profile>/cordis.patch.yml/yaml` 中唯一静态 `id` + `name` 行的 `disabled = !enabled`。替换已有布尔值或在受支持的块/流格式插入缺省字段；保留其他内容、注释、BOM/CRLF。动态值、重复身份、含 insert 的混合文件、分组、无 name 覆盖行及原生管理器必需组件只读。 |
| 独立 Claude/DSH Skill、独立 MCP、项目、随包安装原文及其他未支持来源 | 继续读取状态、展示依据与只读原因；不开放新的独立开关。插件附带组件随父插件配置变化，不单独修改正文或子开关。 |

公共 `.agents` 资源的列表总状态仍按约定显示已启用；在详情的各 Agent 绑定旁分别切换。ZCode 禁用仅标记 ZCode，不改公共文件，也不批量禁用其他 Agent。Codex 公共 Skill 的写入仍未开放。

没有现成配置文件不会自动创建整个客户端配置；重复键、非布尔开关、非法结构与不安全路径拒绝写入。全面控制、项目控制、安装更新及批量操作未实现。

## Claude/DSH 机制依据与生效边界（2026-10-04）

Claude 插件的用户开关与设置优先级依据[官方插件清单](https://code.claude.com/docs/en/plugins-reference)及[设置文件与优先级](https://code.claude.com/docs/en/settings)。本次仅保存用户设置，项目/本地项目/组织覆盖和插件依赖可能影响最终生效；不伪造已加载、不承诺等同原生命令的依赖处理，不自动连带修改其他插件。用户级切换不改项目绑定。

DSH 本机 `~/.dsh/app/node_modules/@deepseek-ai/dsh-plugin-manager/lib/index.js` 的 `writePluginEnabled` 明确写入 `disabled: !enabled`，`setPluginEnabled` 调用它后另行 reload。本次只读取源码核实机制，不导入或执行客户端代码、不连接 manager、不调用 reload。为避免猜测组合层，本次仅开放已有用户 patch 内唯一静态名字/身份的行；不为随包声明生成用户覆盖、不选择 bundle、不推断其他层叠结果。管理器必需组件使用该源码的保护列表继续只读。

所有新开关沿用后端重扫、路径边界、文件身份、计划摘要、鉴权/CSRF、备份与精确恢复；准备计划不写文件，应用时复核绑定和权限，外部编辑拒绝覆盖。DSH 新增 YAML 目标也支持持久化、恢复与中断恢复。

## 验证与证据

ZCode 支持属于静态配置机制及隔离夹具验证，不标记为真实客户端运行验证。开发期间未切换本机真实资源、未执行客户端；写入与恢复测试全部使用隔离目录。

新增隔离测试覆盖 Skill、插件、MCP 单项启停、公共 Skill 的单 Agent 覆盖、其他配置与资源摘要不变、精确恢复、只读来源、权限撤销、外部编辑冲突、重复键与非法开关。隔离单元测试另覆盖旧索引迁移和显式只读保留；浏览器验证默认开放时配置不变、三类直接切换、公共资源禁用标注、缓存只读及原有 Codex 控制流程。

新增 `tests/profile-controls.test.ts`（10 项）与 `tests/browser/profile-controls.spec.ts` 覆盖两客户端默认启停、缺省字段、单值修改、精确恢复、权限迁移/撤销、外部冲突、缓存/项目/子资源/动态值/必需组件只读、无独立 manifest 的明确 user 安装登记、脱敏和网页直接切换。真实来源只做静态只读核对；原生执行未开启。最新验收结果见开发接续说明。

本机有限只读核对：Claude 插件 1 个可控制绑定（gopls-lsp 的 user 安装登记），DSH 用户插件行 7 个可控制绑定；4 个用户设置/安装登记/用户 patch 文件摘要扫描前后不变。仅验证可定位配置目标，未实际切换或验证客户端加载。核对脚本和摘要放在 Git 忽略的 `work/profile-toggle-audit.*`。
