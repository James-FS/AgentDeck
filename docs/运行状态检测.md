# 运行状态检测：当前只读范围

更新日期：2026-10-03（Asia/Hong_Kong）。

## 三种状态与证据

| 问题 | 当前证据 | 页面含义 |
| --- | --- | --- |
| 配置是否启用 | 已登记目录的配置静态扫描、Skill 路径覆盖或插件配置关联；记录最近扫描时间 | “配置已启用/停用/未知”只说明扫描所得配置，不说明当前会话已采用它 |
| Skill 或插件是否被当前客户端会话加载 | 当前未接入现有客户端会话的加载状态接口 | “暂未检测”；文件或缓存存在、`enabled=true`、CLI 版本与独立 `skills/list` 均不能证明现有会话已加载，更不能证明 Skill 已执行 |
| MCP 是否在当前客户端会话连接成功 | 当前未接入现有客户端会话的 MCP 启动状态或状态列表 | “暂未检测”；不把配置、进程存在或管理器独立连接测试当作当前会话的连接成功或失败 |

`GET /api/v1/runtime` 复用本机认证与同源保护，默认只读取 AgentDeck 已扫描的目录索引，不读取原始配置内容、不启动客户端、模型、Skill、插件、hook 或 MCP。返回逐绑定的配置状态、索引更新时间、会话加载/MCP 连接检查结果与原因。`assessedAt` 是报告生成时间；`observedAt=null` 表示没有运行时观察，不能把报告时间解读为客户端采样时间。当前生产环境未配置会话证据提供方，故 `clientSessionId`、`threadId` 与 `evidenceSource` 均为 `null`。未知配置不视为运行失败。

旧目录数据里的 `runtime=active/inactive/pending` 不作为运行证据。应用配置或恢复后，服务端将该旧字段重置为 `unknown`；页面始终以会话证据报告展示运行状态。配置变更后仍需按客户端要求重载或重启，AgentDeck 无法确认何时生效。

## Codex 接口边界

[OpenAI 官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)列出 `skills/list`、`app/installed`、`mcpServerStatus/list` 与 `mcpServer/startupStatus/updated`。这些接口需要访问对应 app-server；另行启动 app-server 得到的是独立进程的状态，不是 Codex 桌面现有会话。`skills/list` 是可用 Skill 的列表，不能单独证明某会话已加载或执行 Skill。`app/installed` 的 `callable` 是该进程的有效可调用状态，仍需明确线程归属。MCP 的启动状态需要与现有线程关联，并考虑断开、重启与证据过期。当前 AgentDeck 没有这种安全的现有会话连接，故不调用这些接口，也不采集可能含对话或凭据的会话日志。

若以后增加客户端桥接，需要客户端明确提供会话 ID、资源身份、状态、时间及失效通知；连接或调用接口前需单独说明影响并取得授权。管理器独立 MCP 握手只能放在“独立连接测试”，不能写入本报告的会话连接字段。

## 2026-10-03 可行性验证：Codex 0.160.0 守护进程接入面

本节是可行性调查记录；页面与 `GET /api/v1/runtime` 行为未变，仍一律“暂未检测”。调查只运行了短暂的 CLI 帮助、Schema 生成和版本查询进程；未启动新的 app-server/MCP/模型，未读取凭据或会话日志、未修改真实配置。

**2026-10-03 第一阶段探测修正：**经用户授权执行 `codex app-server daemon version`，连接默认控制 socket 失败（Windows `os error 10050`）。只读元数据检查发现 `%USERPROFILE%\.codex\app-server-control` 和 `app-server-daemon` 目录均不存在；正在运行的 `codex.exe app-server` 是 ChatGPT 桌面进程的子进程，命令行没有 `--listen`，该 PID 也没有 TCP/UDP 监听端点。因此目前只能确认桌面端有 app-server 子进程，**不能认定它是 CLI 可接入的受管共享守护进程**。遵循预定停止条件，没有启动 proxy，没有发送 `initialize`、`thread/loaded/list` 或 MCP 状态请求。下文列出的协议接口只是条件性可行性，不代表已接入当前桌面会话。

### 版本与进程事实

- 本机 Codex 客户端已由 0.159.2 更新为 **0.160.0**（桌面自管安装，`%LOCALAPPDATA%\OpenAI\Codex\bin\<hash>\codex.exe`，不在 PATH）。此前针对 0.159.2 的原生验收证据对当前客户端已失效，这正是版本证据失效机制的预期表现；0.160.0 不在已验收范围，相关控制保持只读。
- 所装 0.160.0 CLI 提供共享本地 app-server 守护进程的命令；尚未核对 0.159.2 是否也提供这些命令。CLI 帮助文本原文——`codex agents`：“Browse all agent sessions on the shared local app-server daemon”；`codex app-server proxy`：“Proxy stdio bytes to the running app-server control socket”；`codex app-server daemon version`：“Print local CLI and running app-server versions as JSON”；`codex queue`：“Queue a message for an existing session”（`--thread` 接受“Session UUID or exact session name”）。命令存在不证明当前桌面 app-server 暴露控制 socket。
- 进程拓扑（只读进程元数据，2026-10-03 观察）：ChatGPT 桌面进程启动了 `codex.exe app-server` 子进程；其命令行没有 `--listen`，默认控制 socket 目录不存在。该子进程与受管共享守护进程的身份不能等同；另有 `exec-server` 进程。

### 协议依据（来自本机 0.160.0 二进制的离线导出）

`codex app-server generate-json-schema`（纯本地代码生成，输出于 Git 忽略的 `work/app-server-schema/`，内容与所运行的 Codex 版本一一对应）导出 104 个客户端请求方法、83 个服务端通知。与本报告相关的只读方法及字段：

- `thread/loaded/list`：返回“Thread ids for sessions currently loaded in memory”——守护进程内存中已加载会话的 thread id，即“现有会话 ID”的直接来源。
- `thread/list`：返回线程元数据，含 `id`（UUIDv7）、`sessionId`（同一会话树共享的会话 ID）、`status`（`notLoaded`/`idle`/`active`（附 `waitingOnApproval`、`waitingOnUserInput`）/`systemError`）、`createdAt/updatedAt/recencyAt`（Unix 秒）、`cwd`、`source`、`cliVersion`、`name`、`preview`。`notLoaded` 表示仅持久化历史，不得当作“当前会话”。
- `mcpServerStatus/list`：参数 `threadId`、`serverName`、`detail`、分页。逐服务器返回 `name`、`pluginId`（插件 MCP 可关联 `name@marketplace` 身份）、`authStatus`、`runtimeStatus`（`notStarted`/`starting`/`connected`/`authenticationRequired`/`failed`/`cancelled`/`disabled`，描述为“Current thread-runtime connection state; null when unavailable or the configuration changed”）、`serverCapabilities`（未初始化成功时为 null）、`toolsError`（工具发现失败原因）。官方文档说明带 threadId 时“复用该线程的 MCP 连接”，不带时发现可能新建连接（副作用）——因此任何调用必须限定 threadId。
- 失效与变更通知（服务端推送）：`mcpServer/startupStatus/updated`（`name`、`status: starting|ready|failed|cancelled`、`error`、`failureReason`、`threadId`）、`thread/status/changed`、`skills/changed`、`configWarning`、`thread/environment/connected|disconnected` 等。
- `skills/list` 仍为按 cwd 的可用性列表（`name/path/enabled/scope/pluginId`）；协议中不存在“某会话已加载某 Skill/插件”的状态概念。

### 条件性可实现范围（当前桌面进程尚不可接入）

仅当客户端确实使用一个可访问的受管守护进程，并在明确授权后成功连接其控制 socket，以下接口才可作为该守护进程内会话的候选证据；当前机器尚不满足这一前提：

1. 会话归属：`thread/loaded/list` 给出该守护进程内存中加载的 thread ID；仍须另行证明具体 thread 属于用户当前桌面会话与 AgentDeck 登记实例。`sessionId` 与请求使用的 `threadId` 不能混为一谈。
2. MCP 连接/失败：带 `threadId` 的 `mcpServerStatus/list` 可提供线程范围的 `runtimeStatus`；`connected` 与 `failed` 可分别作为状态证据，`authenticationRequired` 应单列为需要认证。还须验证 `serverName`/`pluginId` 与实例、配置层及绑定精确匹配。官方说明该请求会等待待处理的运行时刷新，不能承诺它绝不会触发 MCP 连接或重连；未经进一步评估和授权，不执行此查询。采样时间也不能当作状态变化发生时间。

不可实现、继续“暂未检测”：Skill/插件的“已加载”状态（协议无此概念，`skills/list` 可用性按既定约束不得充当加载证据）；`notLoaded` 历史线程不得标为当前会话；守护进程不可达时不得把另行启动的 app-server 状态顶替。

### 第一阶段探测结果与后续边界

- 已授权并执行 `codex app-server daemon version`：默认控制 socket 不可达，未取得运行中守护进程版本。CLI 和桌面 app-server 子进程不能据此视为同一可接入守护进程。
- 未执行 `codex app-server proxy`、`initialize`、`thread/loaded/list`、`thread/list` 或 `mcpServerStatus/list`。不能为使探测成功而另启 daemon、重启桌面应用或更改配置。
- 明确不调用：`turn/*`、`thread/resume`、`thread/read`、`thread/inject_items`、`thread/*` 写方法、`config/*Write`、`skills/config/write`、`mcpServer/tool/call`、`mcpServer/oauth/login`、`fs/*`、`plugin/*` 写方法、`marketplace/*`、`command/exec`、`account/*`。响应中的 `preview` 等会话内容字段只丢弃不落盘。
- 若将来有可接入的受管守护进程，连接会产生一个客户端连接记录。官方说明带 `threadId` 的 MCP 状态查询复用线程连接并等待待处理的运行时刷新；是否可能因刷新启动或重连 MCP 尚需核实，不能预先保证零影响。当前桌面进程无法经默认控制 socket 接入，运行状态维持“暂未检测”。官方将 app-server 命令标注为 experimental，字段可能随版本变化。

## 验收

### 2026-10-03 实现顺序：证据接口阶段

已增加可选的 `RuntimeEvidenceProvider` 接口，但正式服务没有实例化提供方，也没有连接客户端。提供方必须先证明线程属于用户**当前客户端会话**，再按同一 app-server 生命周期、实例、会话根 ID、线程 ID、绑定 ID 与配置指纹提供 MCP 状态。`thread/loaded/list` 只能证明线程在 app-server 内存中，不能独自完成“当前桌面会话”归属；任何将来接入的提供方都必须补足这个证明。Skill/插件的会话加载仍固定为“暂未检测”。

报告只接受唯一的当前会话和唯一的精确匹配 MCP 采样，采样最长有效 30 秒；过期、未来时间异常、重扫后指纹变化、服务端重启、会话或线程不匹配、多会话歧义、提供方异常均回退为“暂未检测”，不显示连接失败。`connected`、`failed`、`authenticationRequired` 等各自保留独立含义；采样时间是查询时间，不是状态变化时间。界面在存在有效证据时显示状态、原因、会话与线程 ID、采样时间。该接口只是可注入的证据边界，不能凭类型声明或模拟数据宣称真实客户端已连接。

下一阶段仍受本页“第一阶段探测结果与后续边界”约束：当前桌面 app-server 无可访问的控制 socket，尚无经验证的当前会话归属通道。未经进一步影响说明与授权，不启动 proxy、守护进程，也不调用 `mcpServerStatus/list`；尤其后者可能等待并触发运行时刷新。若未来有受支持的现有会话通道，只读取明确授权的会话状态，并保持 `threadId` 限定，绝不把管理器独立连接测试写入会话状态。

`tests/runtime.test.ts` 用合成绑定与提供方覆盖配置/遗留标志不得伪造运行状态，以及有效、过期、身份不符、重扫、多会话、重复采样和提供方异常的处理。`tests/server.test.ts` 在隔离配置目录验证接口鉴权、凭据不外泄及只读文件摘要。测试不执行客户端或 MCP。
