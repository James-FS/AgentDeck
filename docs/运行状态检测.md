# 运行状态检测：当前只读范围

更新日期：2026-10-03（Asia/Hong_Kong）。

## 三种状态与证据

| 问题 | 当前证据 | 页面含义 |
| --- | --- | --- |
| 配置是否启用 | 已登记目录的配置静态扫描、Skill 路径覆盖或插件配置关联；记录最近扫描时间 | “配置已启用/停用/未知”只说明扫描所得配置，不说明当前会话已采用它 |
| Skill 或插件是否被当前客户端会话加载 | 当前未接入现有客户端会话的加载状态接口 | “暂未检测”；文件或缓存存在、`enabled=true`、CLI 版本与独立 `skills/list` 均不能证明现有会话已加载，更不能证明 Skill 已执行 |
| MCP 是否在当前客户端会话连接成功 | 当前未接入现有客户端会话的 MCP 启动状态或状态列表 | “暂未检测”；不把配置、进程存在或管理器独立连接测试当作当前会话的连接成功或失败 |

`GET /api/v1/runtime` 复用本机认证与同源保护，只读取 AgentDeck 已扫描的目录索引，不读取原始配置内容、不启动客户端、模型、Skill、插件、hook 或 MCP。返回逐绑定的配置状态、索引更新时间、会话加载/MCP 连接检查结果与原因。`assessedAt` 是报告生成时间；`observedAt=null` 表示没有运行时观察，不能把报告时间解读为客户端采样时间。`clientSessionId` 与 `evidenceSource` 均为 `null`，因为目前没有可归属到用户现有会话的证据。未知配置不视为运行失败。

旧目录数据里的 `runtime=active/inactive/pending` 不作为运行证据。应用配置或恢复后，服务端将该旧字段重置为 `unknown`；页面始终以会话证据报告展示运行状态。配置变更后仍需按客户端要求重载或重启，AgentDeck 无法确认何时生效。

## Codex 接口边界

[OpenAI 官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)列出 `skills/list`、`app/installed`、`mcpServerStatus/list` 与 `mcpServer/startupStatus/updated`。这些接口需要访问对应 app-server；另行启动 app-server 得到的是独立进程的状态，不是 Codex 桌面现有会话。`skills/list` 是可用 Skill 的列表，不能单独证明某会话已加载或执行 Skill。`app/installed` 的 `callable` 是该进程的有效可调用状态，仍需明确线程归属。MCP 的启动状态需要与现有线程关联，并考虑断开、重启与证据过期。当前 AgentDeck 没有这种安全的现有会话连接，故不调用这些接口，也不采集可能含对话或凭据的会话日志。

若以后增加客户端桥接，需要客户端明确提供会话 ID、资源身份、状态、时间及失效通知；连接或调用接口前需单独说明影响并取得授权。管理器独立 MCP 握手只能放在“独立连接测试”，不能写入本报告的会话连接字段。

## 验收

`tests/runtime.test.ts` 用合成绑定覆盖启用、停用、未知配置及遗留 `active/inactive/pending`，确认没有伪造运行证据。`tests/server.test.ts` 在隔离配置目录验证接口鉴权、凭据不外泄及只读文件摘要。测试不执行客户端或 MCP。
