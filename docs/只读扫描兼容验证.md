## 状态与来源约定

- `origin` 区分配置声明、缓存包与文件系统资源。`cacheState` 区分缓存存在、缺失和未知。
- `pluginId` 使用完整 `name@marketplace`；`pluginVersion` 保留各缓存版本，不推测哪一版当前加载。缓存路径和 manifest 身份冲突时保留诊断，不冒充配置关联。
- `configurationSourcePath`、`configurationKey`、`configurationEnabled` 指向可核对的配置声明。`enabled` 是静态配置观察，`runtime` 无运行证据时保持 `unknown`。
- 插件内 Skills/MCP 通过 `parentId` 关联对应插件包，详情同时展示包版本、市场、配置来源及缓存状态。
- Claude 安装登记指向不存在的缓存时保留只读条目并标记缺失。缓存版本存在也不等于有启用声明。
- Codex 项目 `.codex/config.toml` 和各客户端项目候选保持项目归属；用户全局条目始终 `projectId: null`。项目重扫刷新全局和所选项目，保留其他项目。
- 真实客户端写入能力没有扩大。缓存包、项目配置和插件内 MCP 均只读。

## 复现

常规回归：`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm test:e2e`。默认浏览器测试使用隔离夹具，真实扫描测试默认跳过。

显式执行本机只读浏览器验证：

```powershell
$env:AGENTDECK_VERIFY_REAL_CLIENTS='1'
pnpm exec playwright test tests/browser/real-client.spec.ts
Remove-Item Env:\AGENTDECK_VERIFY_REAL_CLIENTS
```

该测试把管理器数据库置于 `work/tests`，通过构建后的服务和网页扫描实际客户端来源，独立枚举缓存 manifest/Skills/MCP，对照 API 索引，检查父子链接和只读状态，并比对扫描前后 SHA-256。资源索引、路径与摘要只保留在忽略目录 `work/scan-proof`，截图位于 `work/browser-proof`。不保存真实配置原文。
