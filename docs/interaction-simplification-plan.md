# 页面筛选与操作简化实施方案

制定日期：2026-10-24。

后续筛选精简：资源库筛选以 [资源库筛选精简实施方案](resource-filter-reduction-plan.md) 为最新规范，明确只保留四个常驻筛选，取消本文保留诊断筛选和来源归属筛选的要求，并按新方案兼容旧命名筛选。本文其余已实现的页面状态、扫描和操作简化规则继续有效。

状态：待实施。本轮只制定方案，尚未修改产品代码或执行功能验收。

## 1. 执行目标与优先级

把资源筛选集中到资源管理页面，让按钮作用范围固定，减少重复入口和操作后意外变化。优先复用现有逻辑，减少用户需要理解的概念，不新增复杂的自动联动、规则系统或批量操作。

核心结果：

1. 取消应用右上角的客户端、项目筛选；顶栏仅保留导航和一个刷新入口。
2. 资源库内集中设置关联客户端、项目范围和普通筛选，所有条件直接可见。
3. 项目可用性使用自己的检查表单，不再依赖资源库或顶栏的隐式共享选择。
4. 扫描范围由操作本身确定，不再读取浏览筛选决定扫描范围，也不主动清空筛选或跳转。
5. 来源管理、详情、操作记录减少重复按钮、重复信息和不必要步骤。
6. 保留已完成的资源聚合、内置与仅缓存默认隐藏、收藏、搜索、对比和受限启停能力。

### 与旧方案的关系

这是资源库整理完成后的下一轮交互优化，不重新实施上一轮资源身份聚合。

本文替代 docs/resource-library-organization-plan.md 和 docs/usability-and-visual-improvement-plan.md 中以下旧要求：

- “顶栏是客户端和项目的唯一上下文入口”。

旧文档关于扫描证据、资源身份、默认隐藏、权限、安全和数据兼容的规则继续有效。本文最新明确的交互规则优先。此前讨论过的第二个“恢复默认视图”按钮本轮不实施，只保留一个“清除筛选”。

## 3. 筛选与页面状态

### 3.1 顶栏不再选择客户端和项目

移除右上角两个下拉框及其跨页面隐式影响。顶栏保留面包屑和“刷新当前页面数据”，不在其他位置再复制同一个刷新按钮。

无需重写所有 Pinia store。可以复用已有字段，但需明确它们属于资源库浏览状态，不能继续被扫描、总览、来源、变化或可用性当作全局工作环境读取。

### 3.2 资源库集中筛选

筛选工具栏仍直接平铺、允许换行，不引入“更多筛选”开关，不新增筛选抽屉。

按固定顺序排列：

1. 关联客户端：默认全部，选择具体实例；实例多于一个时显示可识别的名称。它表达“已有扫描关联”，不宣称已加载。
2. 项目范围：全部范围、仅全局、指定项目。指定项目后显示“包含全局资源”，默认勾选。
3. 类型、搜索、配置状态、资源来源、只看收藏等原有普通条件。
4. 显示 Agent 内置资源、显示仅缓存资源：沿用持久化偏好，默认关闭。

“关联客户端”与原“所属 Agent”不能继续保留两套可相互冲突的 Agent 选择。普通 Agent 选项集中到关联客户端；原有公共来源、共享来源、归属未知等证据条件可保留在单独的“来源归属”中，明确它与客户端关联不是同一件事。

资源归类、配置或文件来源等已有诊断筛选可保留为短标签的平铺条件，不再同时新增一个含义相近的筛选。优先消除重复 Agent 选择和重复范围选择，不为减少控件而删除现有证据能力。

项目范围语义：

| 选择 | 结果 |
| --- | --- |
| 全部范围 | 当前客户端条件下的全局和各项目记录；客户端为全部时，另包含独立来源 |
| 仅全局 | 当前客户端条件下，有可靠用户级全局范围证据的记录 |
| 指定项目，勾选包含全局 | 指定项目记录及当前客户端条件下的用户级全局记录 |
| 指定项目，取消包含全局 | 只显示指定项目记录 |

范围未知不能仅因 projectId 为 null 就宣称为全局；保持可识别的未知状态，并在全部范围中可见。执行前核对现有分类，若原有“无项目记录”与“已确认全局”不同，新增边界测试并在 README 说明此次范围语义，不改写原始扫描数据。

独立来源保持未绑定，仅在“全部客户端 + 全部范围”时进入列表。因为范围筛选而被排除时显示一句简短提示和“查看独立来源”动作；该动作明确重置关联客户端与项目范围并选择独立来源，不偷偷授予客户端绑定。

所有条件必须作用于同一条关联记录，防止用一条绑定满足客户端、另一条绑定满足来源，组合出实际不存在的匹配。

### 3.3 条件展示、清除与命名筛选

生效条件集中显示在列表上方，可逐个移除。客户端、项目和“包含全局”的选择必须可见，不允许仅存在于旧页面或后台状态。

只提供一个“清除筛选”：恢复全部客户端、全部范围、全部类型，清除搜索、收藏限定和其他普通条件；保留内置与仅缓存的显示偏好，不改变可用性表单。

命名筛选保存完整资源库条件，包括新增项目范围和包含全局开关。旧记录继续可读；原 projectId 映射为指定项目并默认包含全局，未指定项目时按原 scope 语义映射。

旧条件无法直接映射时，继续以清楚的活动条件标签显示并允许移除，不静默丢失条件，也不保留用户看不见的隐藏限制。新增偏好字段使用兼容默认值，同步类型、Zod、API 和存储，沿用偏好并发写入保护。

### 3.4 项目可用性为独立表单

在此页签内部显示客户端实例、项目、工作目录和“检查可用性”。客户端必须明确选择；工作目录默认使用项目根目录，可修改。

首次从资源库进入时可以一次性带入已明确选择的客户端和项目；用户修改表单后，不反向修改资源库筛选。再次切换页签保留表单，不持续双向同步。

只有点击检查才发起检查，不因输入工作目录的每个字符自动请求。修改任一输入立即把旧结果标为待重新检查，并取消或隔离旧请求，避免把上一次检查冒充当前环境结果。

检查后简短显示可用、禁用、冲突、缺失等结果。文件证据、配置时间和加载未验证的详细解释放入展开内容，保留异常原因和必要边界。

### 3.5 其他页面不受资源库条件影响

- 总览展示全局已登记数据，不能受资源库残留客户端或项目选择影响。
- 客户端、项目页面各自展示管理对象。
- 来源与扫描展示全部已登记独立入口。
- 扫描变化展示现有范围内的记录，单条记录标明客户端、项目或来源；不继承资源库筛选。
- 配置操作记录展示配置写入和恢复结果，不继承资源库筛选。

本轮不为这些页面新增多套筛选。已有确有必要的本页条件可保留，但作用范围必须直接可见。

## 4. 扫描和刷新简化

### 4.1 扫描范围由按钮确定

| 操作 | 固定行为 |
| --- | --- |
| 扫描客户端 | 扫描所有已登记客户端的用户级配置；不因资源库选择缩小范围，不附带扫描全部项目或独立来源 |
| 发现客户端 | 在实际本机发现目录中发现或更新客户端，并扫描其用户级配置；不扫描未登记项目，不自动执行版本命令 |
| 项目行：扫描项目 | 扫描该已登记项目在已登记客户端下的项目资源 |
| 来源行：重新扫描 | 只扫描该独立来源，沿用其现有扫描选项 |

“发现客户端”可沿用现有 discoverUserHome 的显式本机发现实现，开发模式仍保持默认隔离；不得把普通刷新变成实际用户 home 扫描。

调用扫描接口时显式构造参数。不要从资源库筛选或可用性表单读取 instanceId、projectId、scanRegisteredProjects；服务端默认行为也需核对并测试。项目和来源定向扫描继续使用明确的 ID。

扫描完成后更新数据，保留当前页面、筛选和尽可能稳定的滚动位置，不主动 clearFilters、不自动切页。分页仅在当前页已超出结果范围时合理回落。

项目扫描结束可在该项目行显示简短结果并提供“查看资源”。只有用户点击时才导航至资源库并设置所选项目、全部客户端、包含全局；清理与该显式导航冲突的普通条件，保留显示偏好。其他扫描不强行打开资源库。

资源管理页面主操作保留“扫描客户端”，次要菜单提供“发现客户端”。客户端页保留发现和手动登记；项目页保留添加项目和各行扫描。总览主要提供状态与跳转，避免重复铺设一整套扫描按钮。

### 4.2 每页一个刷新入口

顶栏保留统一“刷新当前页面数据”，删除资源表、操作记录等位置正常状态下的重复刷新按钮。错误状态的“重试”是局部恢复动作，可以保留。

刷新资源库时读取最新已扫描目录，不重新遍历磁盘。刷新操作记录时读取记录，刷新其他页面时读取其所需数据。尽量复用已有刷新函数和事件队列，不新增通用插件式刷新框架。

刷新不清空筛选、工作目录、收藏或命名筛选；配置修改成功后自动更新相关数据，用户不用额外点击刷新。保留当前请求序号、事件合并和旧响应保护。

## 5. 页面和操作入口简化

### 5.1 来源与扫描

把“自定义 Skill 资源入口”改为“添加 Skill 目录”。基本流程只有路径和“添加并扫描”，扫描深度、只读跟随链接继续放入已有高级选项。

来源行常驻“重新扫描”“自动更新”开关和“⋯”。自动更新只对应现有独立来源目录监听，不能暗示客户端配置也会自动监听；开关保留错误和不支持状态。

菜单放入深度扫描、强制完整扫描、复制路径、取消登记。说明“取消登记不删除目录和文件”。扫描不完整时展示针对性的“继续扫描”入口；不要为了统一菜单把必要问题动作藏起来。

默认每条来源只显示路径、资源数、最近扫描时间、扫描状态和自动更新状态。深度、限额、缓存复用、原始诊断与逐项发现记录放入展开详情。

### 5.2 资源详情和配置操作

统一约定：名称打开详情、星标收藏、单一可操作配置直接启停、多个独立操作目标进入“管理配置”、次要路径与对比操作放入“⋯”。

“绑定”属于实现术语，用户界面优先写“关联配置”；不必更改内部数据类型。多个记录指向同一原生控制地址时沿用既有目标去重，不重新发明聚合开关。

把仅用信息图标表达的启停预览改为“预览修改”或有明确可访问名称的按钮。普通启停沿用现有直接应用、备份、摘要检查、失败处理和自动刷新，不新增所有操作都需确认的弹窗。

详情默认展示资源摘要、主要路径、内容和各配置的简短状态。分类依据、能力证据、完整配置键、缓存版本等放入现有详情的展开分区，不设计多层向导，不要求再打开第二个详情才能完成日常操作。

### 5.3 扫描变化与配置操作记录

保留现有页面结构，明确命名：资源管理中的“变化记录”改为“扫描变化”；主导航“操作记录”可改为“配置操作记录”，页面标题同步。

扫描变化只展示新增、移除、修改和配置状态变化的扫描结果；不再次渲染完整来源报告、监听、重扫和取消登记按钮。需要处理时提供跳转来源的明确链接。

配置操作记录只展示启停、失败、冲突和恢复结果。把“创建恢复计划”改为“恢复此修改”，点击仍进入原有恢复预览并由用户确认，不能变成直接覆盖配置。

### 5.4 客户端与项目页面

客户端卡片默认保留名称、配置目录、简短状态和必要操作。版本证据、PATH 候选、能力矩阵、原始诊断放入“查看详情”；重要错误在卡片摘要仍可见。

版本检查继续由用户显式触发，不因查看详情、刷新或发现客户端自动执行命令。

项目页面只保留一处正常状态下的“添加项目”入口，消除页标题和列表标题的重复按钮；空状态引导可保留。各项目行提供扫描及明确的查看资源入口。

## 6. 不做的事项与保留能力

不增加批量启停、自动修复、自动同步安装、智能切换上下文、自动删除重复资源、复杂工作区系统或第二套恢复默认按钮。

不改资源身份和来源证据算法，除非新交互暴露实际缺陷并有测试证明；不扩大写入权限，不删除磁盘资源，不改变已验证的公共 .agents 展示约定。

保留：内置与仅缓存默认隐藏、统一实体、独立来源边界、收藏与旧引用、命名筛选、分页内容搜索预算、对比选择、SSE 刷新、物理路径和链接授权、备份与恢复检查。

为减少控件而折叠的是技术细节和次要操作，资源筛选继续平铺；必要错误、冲突、截断与只读原因必须能发现。

## 7. 实施顺序

### A：集中筛选、拆开页面状态

移除顶栏选择；集中资源库筛选、项目范围、活动条件和清除动作；适配旧命名筛选；独立可用性表单；让总览和其他页面摆脱资源库残留状态。

### B：固定扫描、统一刷新

扫描参数与浏览状态脱钩；移除扫描后的清空与自动导航；统一刷新入口与当前页数据读取；核查启停、恢复和 SSE 的自动刷新仍正确。

### C：精简按钮、说明和记录

整理来源行、资源详情、预览按钮、客户端卡片和项目重复按钮；区分扫描变化与配置操作记录；保留必要异常提示和跳转。

### D：验收与文档

完成回归和界面检查；更新 README；新建 docs/interaction-simplification-acceptance.md，记录实际实现、测试结果、截图和限制。

每阶段保持可运行，正常实现选择自行判断。只有重大冲突或必须依赖用户信息时请求澄清，不逐步等待批准。

## 8. 验收矩阵

| 场景 | 必须结果 |
| --- | --- |
| 顶栏及切换页面 | 没有客户端/项目下拉框，没有跨页面隐藏筛选 |
| 资源库选客户端和项目 | 关联与项目范围均在本页可见，不能再用另一套 Agent 选择造成矛盾 |
| 指定项目包含或排除全局 | 结果可预测；未知范围不伪装成全局；其他项目资源不混入 |
| 独立来源被上下文排除 | 显示原因，显式查看动作不自动建立绑定 |
